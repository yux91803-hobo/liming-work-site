# 修改清单 · 2026-11-08（正式站联调暴露的问题：网页验收、点名模型、前台兜底记录）

长期记忆 v1（#90）和测试修复（#91）合并后，正式站真机联调两次未过、都已自动回滚，线上一直是 #89 的版本。两次失败都与记忆改动无关，但暴露了三个已有问题，这次一起修：

- 网页验收太严：控制器在同一页面按顺序连续点击，每次点完只等 0.12 秒、只看一眼。模型做的网页常在下一帧或动画开始后才更新状态，或者动画播放时暂时不响应别的按钮，第一次验收经常不过。之前 7 次 Kimi 网页任务里，第一次验收只过了 2 次；其中一次连两次重试都没过，导致联调失败。现在点击后最多等 1.5 秒看预期变化；不过时说明实际看到的状态（例如「#dragon 没有 class happy」「#wave 的 data-count 是 "2"，不是 "1"」），并提醒检查是连续点击的。给后台的网页说明里写清楚：checks 在同一页面按顺序连续点击，前一个动画没播完也要能响应，expect 写点击后一直保持的状态。检查的总时限从 22 秒放宽到 40 秒，留出等待时间。
- 点名模型：用户已经点名（例如「让 Kimi 画」）时，控制器本来就按用户点名的模型派工；但前台如果在 `--model` 里多写了一个不完整的名字（如 `kimi`），会被当成「未知模型」挡住，前台反复重试后只能回复「这句话已保存，但我暂时没能安排好，请重试」。现在用户已点名时忽略前台写的 `--model`；没点名时写错模型或类型，错误里列出可选值，方便前台一次改对。
- 前台兜底记录：前台一轮用完步数或出错时，在云电脑 `~/.xin/logs/front.jsonl` 记一行（只留最近 200 行）：每次调用的命令形状（选项名和类型、模型、依据取值）和错误，不记标题、要求、要记住的话或用户原话。联调测试按约定不在 CI 日志里输出模型过程，这条记录让以后这类问题能在电脑上查到原因。
- 排查时在云电脑上用真实前台模型、替身命令（不建任务、不写数据）对比了新旧设定各 5 次：两版都一次就正确派出 Kimi 网页任务，记忆改动没有让前台多花步数。
- 新增测试：真浏览器验收（稍后才更新的页面能过、一闪而过的 class 和错误取值会给出具体说明；旧逻辑对「0.5 秒后更新」的页面判失败）、点名模型时宽松 `--model`、未点名时的可选值提示、兜底记录不含用户文字。
- 旧记事本补导入：原来只在第一次用记忆库时导入一次。两次回滚期间正式站跑的是旧版本，小芯记的新内容仍写进 `memory.md`，以后不会再进记忆库。现在每行导入后记下摘要，`memory.md` 有新行时只补导新行（待确认）；用户改过或忘掉的原行不会回来；云电脑上已有的旧格式导入记录按已导入的原文接上。
- 新增 `docs/xin-handoff.md`：交接说明（做到哪了、还剩什么、怎么做、坑）。
- 预览页浏览器测试偶发失败（未改动的 main 上 3 次失败 1 次）：预览页设置 srcdoc 后立即显示画面，测试在作品脚本绑定点击之前、或表情字体加载导致按钮移动之前就点了。改为等作品文档加载完、字体就绪后再点；判断内容不变。修改后连跑 8 次全过。
