# 小芯：终端打开不重放、在做的活跟着最新消息走（2026-11-17）

站长 2026-11-17（看了正式站「查一下电脑上有啥啥软件」那一轮）：

> 兄弟，我每次点开这个，都是从头在加载一遍，不符合逻辑，然后图一的那个要跟着相应的最新对话下面，不然我还得翻上去找着看

复述以后站长回「可以」。

## 要什么

1. **点开「小芯的电脑」不从头重放**。现在每次打开都把这件活之前的每一步用打字机重新敲一遍（`site/xin/term.js` 的 `paint`：刚打开「重放 1.2 秒」），从开头滚到最后。改成：一打开，已经发生的步骤一次画好，停在最下面（最新那一步），往上翻能看；只有打开以后新来的步骤才一个字一个字敲。做完的活第一次打开从电脑上读一次记录，之后再开用读过的（这一点原来就是这样）。
2. **派出去的活那个框跟着最新消息走**。现在框在派活那一条回答里面（第四轮定的「那段话下面一个框」），接着聊别的就被顶上去，要翻上去找。改成：
   - 在做的时候（排队、在做、正在停），框一直在最新一条消息下面；接着聊，新消息插在框上面，框留在最底下。几件活一起做，按派出去的先后叠在最下面。
   - 派活的那段话（「好嘞，我这就去……」）留在原处，框不再塞进它里面。
   - 做完、没做成、停了、等你确认：框收成一行（「✓ 任务名 · 用时」，和现在一样），停在这一刻聊天的最后；结果接在它下面（不画头像、不写「小芯」，和现在一样）。之后再聊，它跟着往上走。
   - 等你确认以后又接着做：框回到最底下，做完再停在那时候的最后。
   - 刷新、换回这个对话：在做的照样在最底下；做完的框和结果按做完的时间排在各轮之间（以前的「结果按结束时间插在各轮之间」）。

## 不要的

- 不改控制器、不改存的记录：只改网页的画法（`site/xin/chat.js`、`site/xin/term.js`、`site/xin/chat.css`）。
- 前台这一轮跑过命令的那一行（「用时 9 秒 · 运行 2 条命令」）还在那条回答下面，不跟着走（那一轮已经结束）。
- 不加新的按钮或卡片；框还是那个框（点开是终端）。

## 怎么做

- **终端**：`paint` 把已经有的事件排进打字机以后马上一次画完（和「减少动态」时一样走 `drain`），滚到最下面；`push` 来的新事件照旧逐字敲（积压多了加速那套不变）。读完历史后的 `fill` 同样一次画好。
- **框**：每个框套一条不画头像的消息（`.xc-m.xc-ai.cont.xc-tbw`，和结果那条同一种排法），在做的带 `dock`，放在消息列表最后；`put`（新消息）和「思考中」那一行都插在第一个在做的框前面。框的状态变了（`paintBox`）：变成不在做 → 挪到这时候的最后（`put` 的位置）；又在做了 → 挪回最底下。结果找框（`resultAfter`）：框还在最底下就先把它落到最后，再把结果接在框（和它后面已经有的结果）后面。
- **历史**：派活那一轮里的 `task` 事件，在做的才画框（到最底下）；做完的不在那里画，按结束时间插结果的地方先画框、再画结果。往前翻「更早的消息」时，临时列表里和现有列表重复的框去掉（和结果一样）。

## 参考

- Claude Code 命令行：后台在跑的活一直显示在最底下输入框旁边，做完才从那里消失，结果按发生的时间进对话。
- tmux（`attach`）：重新接上一个会话时直接显示当前屏幕，不把之前的输出重放一遍。
- impeccable、frontend-design：一个东西一个位置、看过的动画不重放；ui-ux-pro-max：状态变化给反馈、不打断。
