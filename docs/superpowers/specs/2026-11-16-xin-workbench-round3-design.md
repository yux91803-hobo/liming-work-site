# 小芯工作台第三轮（2026-11-16）

站长看了 #154（天启入口、小芯的电脑）上线后提的五件事（原话摘要，配了四张手机截图）：

1. 「图一侧边这个感觉还是之前的模版，不好看。」
2. 「图二从天启切到小芯，嗨，我是小芯的文字会闪一下，还有有些文字太口语化了，你要去看 skill 里面的标题文字啥的命名标准。」
3. 「图三，我希望的命令行像这样。」（Claude Code 的欢迎页：像素夜空、星星、月亮、云，小螃蟹站在点线地平线上，`Welcome to Claude Code`；改动带行号、语法高亮，整行红绿底）
4. 「你现在小芯的思考文字都是固定的那几个，我希望的是 grok bot 的那样根据用户的输入问题，显示相关的文字，你可以去看看别人咋设计的。」
5. 「图四，我问的一个问题他先是发去弄，但是就结束了，过一会儿才回的消息，期间不像 grok bot 那样虽然都是派后台任务，但是他也是动态的在动，这样就知道他在干活。」

实现与自查：Claude Code（同一会话，没有另一位审核）。一个 PR 上线。

## 先查清楚的事实（看代码 + 只读查了小芯电脑上的记录）

- 图四那一问（北京 12:02）：前台 10 秒回了「这就去查查」并派出后台的活「查询 Gemini 4 Hydrogen 评测与表现」；这件活由 Antigravity（Gemini 4 Hydrogen）做了 32 秒：先后 3 次网页搜索（`Gemini 4 Hydrogen review benchmark performance` 等），然后写好答案。
- 网页这 32 秒里能拿到的只有任务摘要的 `activity`：控制器只认最后一条事件，搜索只在**做完**时记一条 `tool_end WebSearch`，于是 `activity` 是「执行完：Gemini 4 …」；网页的 `taskVerb` 只认「在执行：」开头的命令，其余一律退回那 10 个轮换的字（思考中、琢磨中、盘算中……）。所以最下面那一行虽然在，内容始终是固定的字，看不出它在搜什么——这就是「不动」。
- Antigravity 后台：它的 stream-json 只有工具步骤（`step_update`，搜索 / 读网页带 query、url）和回复文字，**没有思考内容**；思考摘要只存在它自己的对话数据库里（英文，例：「Initial search results seem promising. Expanding the search with specific benchmark names…」）。
- 前台（Antigravity 的 ACP）：会推 `agent_thought_chunk`。实测一问：1.8 秒来第一段思考、3.9 秒来回答；思考是英文摘要，开头常是一句客套「I'm thinking through how to approach this.」。控制器现在只数了字节，内容丢了。
- 天启（Harness）的 `thinking` 事件、Codex 的 `reasoning` 条目，`vm-events.mjs` 里都直接丢掉。

## 参考了谁

- **Grok**（站长点名）：状态行跟着它真正在做的事换——「在搜 X」「在读 Y」，思考的内容可以展开看。
- **openai/codex** `codex-rs/tui/src/chatwidget.rs`：推理摘要流进来时取第一个 `**粗体**` 当状态行标题（`extract_first_bold`），没有就保留原来的；工具调用显示成「动作 + 对象」。
- **open-webui** `backend/open_webui/utils/middleware.py`：联网前先用一个小的「任务模型」从用户这句话生成搜索词，发 `status` 事件（`web_search_queries_generated`），界面显示「正在搜索 “…”」；做完写「搜索了 N 个网站」。
- **impeccable** `reference/clarify.md`：加载文字要说出真实在做的操作，不编造进度；同一个概念始终用同一个词，「界面里不为了文采换说法」；动作用「动词 + 对象」。
- **frontend-design**：按用户能懂的说法命名；按钮写清点了会发生什么；同一个动作在整个流程里叫同一个名字；不说多余的话。

## 1. 「它在干活」一直在动（第 5 条）+ 思考文字跟着问题走（第 4 条）

**做法**：状态行永远显示「此刻真实在做的事」，按来源从具体到概括：

1. **真实的一步**（最具体）：搜索「Gemini 4 Hydrogen review benchmark」、读网页 deepmind.google、运行 make -j4、修改 src/tim.c、派出后台任务……做哪一步就写哪一步。
2. **这一轮在想的事**：前台一开始，用网关上最快的模型（DeepSeek V4.1 Flash，思考关掉）把站长这句话（带上一轮对话做上下文）概括成 6–14 个字、动词开头的一句，如「查 Gemini 4 Hydrogen 的评测」「算定时器溢出时间」「看今天的签到记录」。这就是 Open WebUI 的「任务模型」做法；它只决定状态行写什么，不参与回答。5 秒没回、出错、前台已经回完都丢掉。
3. **兜底**：「思考中」。不再轮换「琢磨中、盘算中……」这些词（impeccable：不为了文采换说法）。

**控制器**：

- 前台：开始时并行请求上面那句概括，回来就记一条 `{t:'think', text}`；ACP 推来的思考摘要也记成 `{t:'think', text, model:true}`（去掉开头那句客套，取第一句，最多 160 字）——它是英文，**只在「小芯的电脑」终端里**按 Claude Code 显示思考的样子画成暗色的一行，聊天的状态行不放英文。
- Antigravity 后台：搜索、读网页的步骤**一开始**就报（`item.started`，带搜索词 / 网址），做完再报一次；读网页单独记成「打开网页」，不再混成搜索。
- `vm-events.mjs`：Codex 的 `web_search` 开始时也给一条；`reasoning` 条目给 `think`；天启（Harness）的 `thinking` 给 `think`（DeepSeek 多半想的是中文）。
- 任务摘要的 `activity` 改成「最近一个有意义的步骤」：`在搜索：…` / `在读网页：…` / `在执行：…` / `在修改：…` / `在想：…` / 它自己说的话；做完一步、还没开始下一步时写「在看结果：…」。

**网页**：

- 「正在输入」那一行：先「思考中」，概括来了换成概括，做哪一步换成那一步（`swapText` 上下换），一步做完回到概括；秒数照走。
- 后台那一行（`.xc-bgrow`）改成两行：上面是任务名，下面是此刻那一步 + 秒数（步骤一变就上下换一下，动词那段有一道光扫过去）；有一件以上写「等 N 件」。后台有活、正看着这个对话时，任务摘要 2 秒取一次（原来 4 秒）。
- 终端里：`think` 画成暗色的思考行（✻ + 文字），概括那条画成灰色的一行「在想：…」。

**不做**：不把后台的思考翻译成中文（要多一次模型调用，且思考摘要 Antigravity 不流式给）；不为前台另开一路流（ACP 已经在推）。

## 2. 终端照 Claude Code 命令行重做（第 3 条）

站长给的图是 Claude Code 在 VS Code 终端里的欢迎页。照它改「小芯的电脑」里的内容，外框保持上一轮的像素窗口（方角、2px 边、硬阴影），但标题栏更薄：

- 第一行橙色（这里用小芯的琥珀色）`小芯的电脑`，后面暗色写工作目录。
- 一条点线。
- **像素夜景**：深底上几团用棋盘点画出来的灰云、几颗 `*` 星星（慢慢一闪）、右上角一弯像素月牙；小芯的全身像素小人站在下面那条点线地平线上（Claude Code 那里是小螃蟹）。整幅是一张 SVG，`shape-rendering: crispEdges`，跟着终端宽度铺开，云、星、月的位置按格子算好，不随机。
- 再一条点线，下面是「> 要求」和各步。
- 每一步照 Claude Code：圆点 + `动作(对象)`，结果在 `⎿` 折角线下面（字符都画，不用 emoji）。
- **改动**：照图里的样子——左边行号槽（旧 / 新行号按 `@@ -a,b +c,d @@` 算），删的整行暗红底、加的整行暗绿底，行内代码按 Monokai 配色高亮（关键字、字符串、数字、注释、函数名、类型），`@@` 那行换成一行暗色的「第 N 行起」。
- 打开网页：不再画小浏览器卡片，照终端写法：`打开网页(st.com/…)`，下面 `⎿ 标题：…`。
- 打字机、减少动态、只轮询开着的那一页，都和上一轮一样。

## 3. 侧边栏重新设计（第 1 条）

原来是一条条「图标 + 文字 + 箭头」的列表、选中项一张白卡片——就是通用聊天应用的模板。改成和工作台一套的「芯片与纸」：

- **顶上**：小芯的像素小脸（不要绿圈）、「小芯」、下面一行状态（在线 / 休息 / 在做 N 件事），手机上右边收起。
- **两颗键帽按钮并排**：「新建对话」「新建天启对话」——像键盘键帽：1px 边、底下 2px 硬阴影，按下去下沉 1px；天启那颗是深蓝底配星。原来两行大圆图标的按钮去掉。
- **搜索**：一条细的输入框样子，右边 ⌘K / Ctrl K。
- **主对话**：单独一块，左边一道琥珀色的竖条，写「主对话」和最后一次更新时间，在回话时竖条上一个像素点在闪。
- **对话列表**：按时间分组（今天 / 昨天 / 7 天内 / 更早），每行左边标题、右边时间；选中的不再是白卡片，而是纸色底 + 左边 2px 墨色竖条；在回话的对话标题前一个琥珀色像素点在闪；天启的对话标题前一颗小星。
- **底部一排**：「每日任务」「设置」两颗小按钮并排，下面「退出登录」；设置照旧原地展开。
- 电脑上常驻、手机上抽屉，结构一样。

## 4. 修标题闪一下 + 文案按 skill 的标准改（第 2 条）

**闪的原因**（逐帧截图看到的）：切回小芯时，标题外面那层还是「天启」的宽度（66px），新标题「嗨，我是小芯」被挤成两行、和正在淡出的「天启」叠在一起，第一帧就是一团乱字，然后宽度才慢慢撑开。改法：欢迎页的标题不做宽度动画，两段字居中叠在一起交叉淡入淡出，并且不换行。

**文案**：照 impeccable 的 clarify（动作用「动词 + 对象」、同一个概念用同一个词、状态说真实在做的事、出错说什么失败了）和 frontend-design 的写作部分。小芯头顶气泡里说的话是它的性格（「我弄好了」「记住啦」），不改；改的是界面上的标题、按钮、状态和出错提示：

| 原来 | 改成 | 理由 |
| --- | --- | --- |
| 嗨，我是小芯（空白页大标题） | 小芯 | 和「天启」一样只写名字；招呼不是标题 |
| 和小芯说点什么… / 和天启说点什么… | 给小芯发消息 / 给天启发消息 | 动词 + 对象，说清这个框做什么 |
| 新对话 / 新的天启对话 | 新建对话 / 新建天启对话 | 动词 + 对象，两颗一致 |
| 思考中、琢磨中、盘算中、酝酿中、捋一捋、掂量掂量…… | 思考中（其余换成真实在做的事） | 不为文采换说法 |
| 在电脑上忙 | 执行中 | 状态说真实的操作 |
| 等前面的做完 / 停下来 | 排队中 / 正在停止 | 同上 |
| 干完了 · 用时 2 分钟 · 4 条命令 · 改了 2 个文件 · 看了 1 个网页 | 已完成 · 用时 2 分钟 · 运行 4 条命令 · 修改 2 个文件 · 打开 1 个网页 | 和每一步的动词一致 |
| 在电脑上做了 48 秒 | 用时 48 秒 | 去掉多余的话 |
| 没做成 / 停了 / 停下来等你 | 失败 / 已停止 / 等待确认 | 状态词 |
| 接着做（终端里的分隔） | 继续 | |
| 读不出来： / 没送到： / 停不下来： / 没改成： / 没归档成： / 没弄好： | 读取失败： / 发送失败： / 停止失败： / 修改失败： / 归档失败： / 保存失败： | 出错先说什么失败了 |
| 看小芯在电脑上做了什么（头像的读屏名） | 查看执行过程 / 查看正在执行的步骤 | 动词 + 对象 |
| 回得快，想得浅一点（思考强度说明，几条） | 思考较少，回复更快（同一套词：思考、回复） | 去口语 |
| 电脑刚醒，网络在热身，稍等一下 | 电脑刚唤醒，正在连接网络 | 说真实在做的事 |

术语表（以后都按这个写）：对话、主对话、天启对话、后台任务、执行过程、运行（命令）、修改（文件）、搜索、打开网页、思考、完成 / 失败 / 已停止 / 等待确认。

## 测试怎么改

- 新单元测试：前台概括的清洗（太长、带引号句号、空的、像在回答问题的都丢掉）；ACP 思考摘要去掉开头客套、取第一句；Antigravity 搜索开始就报、读网页单独记；`vm-events` 的 `web_search` 开始、`reasoning`、Harness `thinking`；`taskActivity` 的几种写法。
- 浏览器测试：正在输入那一行先「思考中」再换成概括、再换成一步；后台那一行两行、步骤变了跟着换、2 秒取一次；终端的夜景、行号和高亮、思考行；侧边栏的新结构（键帽按钮、分组、底部一排）；欢迎页切换时标题不换行、不叠成两行；文案改动跟着改检查的字（行为不变，不删测试）。
- 「思考中 · 1 秒」那条计时检查保留（第一句仍是「思考中」）。
