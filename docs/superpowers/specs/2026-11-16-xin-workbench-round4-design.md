# 小芯工作台第四轮：派活那一轮合成一条、去掉头像上的终端小标、三个小问题

北京时间 2026-11-16 晚。实现和自查：Claude Code（同一会话，没有另一位审核）。

## 站长原话

> 图一你上面的终端小标没去掉，然后不需要这个小标，你不是做了个框框把思考中框住了么，我点那个就可以打开终端就行，还有我让他干的这个活不要让他分成两个独立的话来答，可以弄成他要去画那段话下面搞一个框框加载，显示思考过程的话，左边不要显示头像，然后点开这个加载框可以看到终端，你能懂我意思么，你可以复述一遍我觉得没问题你就开始做

我复述后（含下面「我加的三点」），站长回：「可以开始做。然后这个网页有显示bug，然后现在终端从下面弹出来会有卡顿，不够丝滑，还有图二，打开网页和打开预览其实重复了」

## 要做的（站长确认过的复述）

1. **去掉头像上的终端小标**：回答头像、「思考中」框里头像右下角的 `>_` 小方块都不要。想看终端就点框：「思考中」那个框整条都能点（头像留着，只去小标）。
2. **派活的那一轮合成一条回答**：
   - 小芯先说「好嘞，我这就去画……」，这段话下面接一个加载框；框左边不放头像，框里写它此刻真实在做的那一步，秒数在走、点在跳；点框打开终端。
   - 做完后框收成一行（✓ 名字 · 用时），点开还能看那次的终端记录；结果（「我画好了。打开网页」和下面的操作）接在框下面，还是同一条回答。刷新页面后也一样。
3. **我加的三点（站长同意）**：
   - 聊天最底下那条单独的后台进度去掉（和框重复）；顶上「小芯」旁边的数字照旧。
   - 活没干完时又聊了别的：结果照样回到原来那条回答下面，聊天顶上冒一个小提示，点一下滚过去。
   - 没派活、只在前台跑过命令的回答：回答下面留一行同样的框（「用时 9 秒 · 运行 2 条命令」），点开看那一轮的终端。

## 三个小问题（查过原因）

- **网页卡片显示不对**：小芯电脑上检查网页时，按 1280、390 两个宽度各点一遍，最后在 390×800（手机竖图）上截图；工作台的卡片是 16:10 横框、`object-fit: cover` 取最上面一截，于是只看到页面顶上空的背景和半截标题栏（站长那张「海风鹈鹕单车」本身是好的，鹈鹕画在页面中间）。
  修：控制器检查完后换回 1280×800、重新打开页面、等 600 毫秒再截图（横图，正好 16:10，也不带点击检查改过的状态）；已经有的竖图，卡片里整张缩进去显示，两边垫一层同一张图的模糊底。
- **终端从下面弹出来卡**：底部弹出的动画写的是 `steps(4, end)`（0.22 秒分 4 格跳上来），电脑上的弹窗是 `steps(5, end)`，本来就一顿一顿；关的时候没有动画，遮罩也是一下出现、一下消失。
  修：照 Vaul（emilkowalski/vaul，`src/constants.ts` 的 `TRANSITIONS = { DURATION: 0.5, EASE: [0.32, 0.72, 0, 1] }`、`src/style.css` 的 `slideFromBottom` / `slideToBottom` 和遮罩 `fadeIn` / `fadeOut`）：面板 `translate3d(0, 100%, 0)` 滑到 0，缓动 `cubic-bezier(.32, .72, 0, 1)`，进 0.42 秒、出 0.28 秒（出比进快）；遮罩同一条曲线淡入淡出；`will-change: transform`。电脑上的弹窗改成从点的位置放大 0.92→1 加淡入，连续缓动。减少动态效果时不动。
- **「打开预览」和「打开网页」重复**：网页做好时控制器写的结果是「我画好了。[打开预览](地址)」，下面一行又放「打开网页」。
  修：结果文字里已经链到同一个预览时，下面不再放「打开网页」；控制器那句改成「我画好了。[打开网页](地址)」，和工作台卡片的按钮同名（旧记录里的「打开预览」照旧能点）。

## 做法（比较过的）

- **A. 只改网页的画法（选这个）**：存的聊天记录不动——派活那一轮里本来就有 `task` 事件，结果本来就是带 `taskResult` 的一条；网页画的时候按任务编号找到那个框，把结果接在那一轮后面，不画头像和「小芯」。找不到框（比如派活那一轮在「更早的消息」里还没翻出来）就照旧单独一条。
- B. 控制器把结果写回派活那一轮：要改存储格式、旧记录要迁移，模型看到的上下文也跟着变，风险大，没选。
- C. 结果还是单独一条、只是不画头像：还是两条回答，和站长说的不一样，没选。

框放在哪：放进那段话所在的那一条里面（正文和下面那行操作之间），不另起一条——这样「复制」那一行仍旧只在这一轮最后一条下面（原来的 CSS 规则不用改）；结果作为同一轮的续条接在这一轮最后。派活时还没说话的（先派后说），框先占一条，后面说的话填进这一条的正文，保证话在框上面。

参考 open-webui `src/lib/components/chat/Messages/ResponseMessage/StatusHistory.svelte`：进度放在同一条回答里，只露最新一行，没做完时 `shimmer`，做完留一行；整行一个按钮，里面的字 `pointer-events-none`（字一直在换，点击不能落在会被换掉的元素上——#156 修过同类的「点头像那一下会丢」）。

## 细节（我定的）

- 框：两行——上面任务名，下面此刻那一步 + 秒数，后面三个点；那一步有一道光扫过（沿用第三轮后台那一行的写法，`xcshim`）。等着排队写「排队中」/「准备中」。
- 做完那一行：图标 + 任务名 + 状态 + 用时 + 「›」。完成写 ✓ 和用时（「✓ 编译 blink · 用时 2 分钟 ›」）；没做成写「失败 · 用时 40 秒」，停了写「已停止」，等你确认写「等待确认」——和终端结尾那行用同一套词。
- 顶上的小提示：「编译 blink 做好了」/「没做成」/「需要你确认」，点了平滑滚到结果并轻轻闪一下；结果出现在眼前或点过就收起。
- 前台过程那一行：用终端结尾同一句（`LimingXinTerm.summary`：「用时 9 秒 · 运行 2 条命令」），放在这一轮最后一条的正文下面。
- 读屏：框是按钮，念「编译 blink，进行中，查看正在执行的步骤」/「…，已完成，查看执行过程」。

## 不做的

- 不改存储、不迁移数据。
- 框上不放「停止」「修改」（在工作台和「详情」里有）。

## 实际做成的样子（和上面不一样的地方）

- 做完那一行写「用时 2 分钟」（带「用时」，和终端结尾那句一样），不是光写「2 分钟」。
- 结果接在派活那一轮的最后一条后面（不一定紧贴框）：那一轮框下面如果还说了别的，结果在那些话后面——一轮按说话的先后读下来。
- 框在做时用了第三轮后台那一行的两行写法（任务名 / 此刻那一步 + 秒数 + 三个点），只是挪进了回答里、去掉了脸。
