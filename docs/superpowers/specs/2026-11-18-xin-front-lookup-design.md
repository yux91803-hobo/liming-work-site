# 小芯前台自己查简单的资料，查的时候能插话

状态：站长已确认（北京时间 11-18 晚上），随 PR 上线。站长的原话：

- 「前台也不是啥也不做吧，比如简单的上网查资料它可以自己去做，但是我可以继续说话改变任务，antigravity里面有那个插话引导模式的」
- 「反正就是耗时间的任务交给后台，你可以参考Muse」

等「派活算一条消息」那批上线后，另开一个 PR 做。

## 为什么

现在前台只聊天和派活，哪怕查一个跑分也得派后台，再等前台写总结。站长要的是：

- 几下就能查到的，前台自己查、自己答；
- 耗时间的，才交给后台；
- 前台查的时候，站长能接着说话，改变查的方向。

## 现状

- **前台的工具**：在 `site/xin/vm-front-agy.mjs` 里，Antigravity 自带工具发来的 `session/request_permission` 一律回 `cancelled`。前台只能用控制器认的 `xin` 动作：派活、记忆、小人动作。
- **后台的插话**：Gemini（Antigravity）任务由控制器在步与步之间接补充（`vm-runtime.mjs` 的 `steers`，见 `docs/superpowers/specs/2026-11-17-xin-steer-design.md`）；Codex 任务走 app-server 的 `turn/steer`。前台还没有插话。
- **Antigravity 自带的插话**：Antigravity 命令行有没有自带插话接口，网上没查到正式说明。别家的做法：
  - OpenClaw 的 `/acp steer`：在下一个能接的地方送进去，接不住就当普通消息发；
  - Amp 的「Steer, Don't Queue」：不排到这一轮结束，下一个机会就送进去。

## 目标

- **分工**：
  - 前台自己查：只需要搜索、读公开网页，几下就能答的，比如某个模型的跑分、某颗芯片的参数、今天的新闻。
  - 照旧派后台：耗时间的，包括要登录、下载、写代码改文件、操作设备、翻很多来源慢慢整理的。
  - 依据：Muse 的「How You Work」（自己动手）和「Subagents」（交出去的是要跑一阵的活），对照见 `docs/xin-prompt-v2.md`；还有站长 11-18 的「耗时间的任务交给后台」。
- **插话**：前台查的时候站长接着说话，话送进正在做的这一轮，手上这一步做完前台就能看到。前台自己判断是改查的方向，还是另一件事，查完再说。
- **页面**：
  - 查的过程就是「思考中」那一条：一直在动，点开终端能看到搜了什么、读了哪个网页。
  - 答完下面留一行「用时 · 搜了几次」。
  - 不派后台，也就没有任务框，没有等总结的空档。

## 不做

- 不给前台读写文件、跑命令、登录、下载。
- 不改后台的流程。
- 不改天启。

## 做法

1. **先看清电脑上的实际情况**：在 li 上只读地看前台会话里搜索、读网页这两样工具发来的权限请求长什么样（`toolCall.kind`、标题），以及 `initialize` 返回的能力里有没有插话类的接口。调 InstaBox 之前先读 https://instabox.sh/llms.txt 。
2. **只放开两样**：只批准搜索、读网页（按看到的工具名和 kind 列白名单），其余照旧回 `cancelled`。前台提示词「你在这里怎么干活」的第 1、2 条改成：几下能查到的自己查，耗时间的派后台。前台这一轮加一个时限，到了还没查完就收尾：说清查到哪了，剩下的派后台。
3. **插话**：Antigravity 有自带接口就用。没有就用「下一步送进去」：
   - 前台在查的时候站长又发了话，控制器等当前这次工具调用结束；
   - 取消这次 prompt，会话保留，查到的东西还在；
   - 马上在同一个会话里发新的 prompt：「兄弟中途补充：……（接着刚才的查）」。
4. **页面**：前台在查的时候站长发的话不再排到这一轮结束后，直接发出去、显示在聊天里，回答出来时照常接在后面。
5. **测试**：用测试里已有的假 Antigravity（ACP），模拟搜索、读网页的权限请求、别的工具被拒、中途补充和时限收尾。

## 取舍

- **用 Antigravity 自带的搜索和读网页**（选这个）。
  另一条路是控制器自己做搜索工具，但那得有搜索来源：没有搜索 API 的密钥，抓搜索引擎的页面又不稳，会慢、质量差。
- **插话「下一步就送进去」**（选这个）。
  另一条路是「等这一轮完了再说」，那就是现在的排队，站长要的是能中途改方向。

## 留给实现的

- 白名单里工具的具体名字（按电脑上实际看到的定）。
- 前台查资料的时限，建议 3 分钟。
