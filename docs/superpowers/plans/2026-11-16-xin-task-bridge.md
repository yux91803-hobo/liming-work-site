## 行为与边界

- 旧实现将 `{op,text}` 放在可复用的工作区 io。旧请求可被下一轮消费；处理异常时 finally 仍删除请求，提交成功但回复未写成又有重复窗口。
- 新建的沙盒轮次才选择 `bridgeProtocol=1`，需要已有的执行尝试协议。执行器从启动时的元数据取得身份；不升级旧轮次，不读取当前新身份替代旧身份。
- 每个 run/attempt 使用单独的 0700 io 目录。只向执行器传局部工作区副本，不修改会话里的规范工作区。旧 shim 仍从 `XIN_TASK_IO` 取目录，不在共享脚本中硬编码身份。
- 普通 Codex、app-server、Antigravity 的容器与父进程消费者使用同一个局部副本；只挂载当前 io，不挂载其可写祖先。未知协议、缺身份和异常路径拒绝启动，不能降级去扫旧目录。
- 文件桥只接受 remember/ask/note。控制器从运行元数据派生任务，并核对源身份、目标、当前轮次、是否结束和 tasks 锁；模型不能借此提交任意命令或自行授权宿主能力。
- 请求编号为既有文件名中的随机 ID。SQLite `commands` 的稳定键绑定 run/attempt/请求 ID，摘要绑定完整参数；记忆、提问或 note 的事件/计数/handoff 与回执在同一事务提交。相同请求返回原回复，不同内容报冲突。
- 已提交请求在轮次随后结束时仍可取原回执；结束后的新请求被拒绝。旧尝试无论有没有回执都不能改变当前尝试。
- shim 发布请求时同步文件和目录。只有得到确定字符串并成功持久发布 reply 才消费 request；未知交付、临时失败或回信发布失败保留原请求 ID，下次查同一回执。畸形请求不得永久堵住队列。

这是队列中已持久请求的逻辑副作用保证，不是所有工具的权限系统，也不覆盖 runner 整体收尾、模型尚未入队的输出或任意外部副作用。同 UID 的编号不是安全凭据。
