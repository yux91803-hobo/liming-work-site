# 常驻状态进程和兼容桥（第 1 批第二块）

基线 main `8ee5bd6`，接着 #139。范围按已确认设计 §6.3–6.6：本块能在临时目录中运行真实状态进程与两层桥，线上仍为 legacy；Worker 开关、持久服务和正式切换另批。

本批不增加依赖、服务器或付费接口，不删除状态/投影，不改变天启和学习偏好。兼容基线保留 legacy 路径。操作和单次写都先核对所有权，失败不回落为本地写者。

实施顺序：

1. 本机 socket 协议、异步客户端和同步适配器。请求/响应有协议号、编号、大小和时间限制；连接前失败是未执行，请求发送后断线/超时是不确定，不自动重试。同步适配采用设计预留的小客户端进程，避免复制 synckit 对迟到通知、端口读取和工作线程启动失败的复杂处理；用实测开销判断是否以后换线程。
2. 将每次操作的 locked/key/run 放进调用上下文，抽出分派入口，保留原参数摘要和响应。状态进程内的同步操作直接调用，等待网络的部分允许其他请求报告，不能整请求 await 串行导致登录回报死锁。
3. 状态进程持 owner 独占锁，初始化一次；提供正常退出、排空回 legacy、进程死亡后 kernel 记录保留、父管道断开后退出。启动前后核对同目录的未兼容控制器，发现时不接管。
4. journal.write/append 的单次写转给主人；其他进程不能直接开状态事务/派发。未持写权的数据库连接为原生只读，写权释放时关闭可写连接，旧句柄不能跨越切换。
5. 记忆、整理、检索和学习的修改通过固定名称的操作，不传函数或 SQL。保留已有证据/遗忘/预算保证；补齐 schema 初始化的读写边界。初始化缓存不得早于事务提交。
6. 保留原测试，旧模式完整回归；临时数据验证新旧模式相同的发送、任务、记忆和审批行为，并验证并发、提交前后崩溃、失联、迟到回应、暂停恢复和往返切换。不能为了两模式测试删除原来的文件锁保证。

后续正式切换的必要条件仍包括完整写者清单、旧版本排空、恢复/收尾暂存和持久服务；本批不能声称生产已经完成单写者迁移。Worker 期望模式必须带部署代号，旧 isolate 的无版本配置不能反复切换主人。

参考：tmux client.c 的连接/服务端锁；un-ts/synckit src/helpers.ts、src/index.ts 的同步等待与超时处理；Node 22 的 SQLite readOnly 和 net.Socket 文档。所有权切换和现有控制器的具名操作适配没有同构可直接套用的代码，按本项目实现并做故障验证。

实现补充：发现已有状态 socket 时先以零等待读取所有权记录。只有独占锁忙或明确记录为 kernel 才转发，legacy 记录仍走共享锁；socket 本身不授予权限。接收端始终先持独占锁再监听，转发失败不作为取得本地写权的理由。这避免兼容请求每次先等 250ms，保留故障时拒绝写入的保证。

验收命令为 `npm run check`、`npm run test:kernel`、`CHROMIUM_PATH=... npm run test:e2e`。内核模式重用原有控制器行为集（13 个文件）；存储算法、schema 事务与 legacy 文件锁测试保留。原有「推送旧响应不能删新订阅」的测试把环境配置提前到服务启动前，原断言不变；常驻服务不读取测试进程启动后才更改的环境变量。

边界：不引入真实电脑故障测试，不操作真实凭据，不声称用户暂停/恢复的端到端投递、未提交执行器收尾暂存和 Worker 模式代号已经做完。`SIGSTOP/SIGCONT` 覆盖的是本地状态进程的暂停语义；真正的 InstaBox 生命周期与正式切换联调留在持久服务那一块。
