# 小芯内核第二阶段：唯一写者、任务调度与执行权限边界

北京时间 2026-11-14。基线：`main` 339c5b0；独立审查见 [接手报告](../../xin-kernel-handover-review-2026-11-14.md)。站长已授权按推荐方案开发、测试和创建 PR，不逐项询问；重大重构不自行合并、部署，不操作真实凭据和不可逆数据。

本文是实施计划，勾选项尚未实施时不得写成产品已经具备的保证。每批独立分支/PR、兼容上一批、可回滚，不把下面所有改动堆进一个 PR。

## 目标与不变量

1. `workflow.sqlite` 的工作流、记忆、学习状态只由内核写；外部 HTTP、执行器、每日任务、空闲整理与清理器都通过受控接口请求变更。
2. Cloudflare 只决定消息持久送达、唤醒、在线身份和时间，不再产生第二套任务执行状态；InstaBox 是计算与数据的所在地。
3. 一个对话同时一轮；并发通道、同目录互斥、依赖、取消、等待确认、模型回退、项目验收/写回等行为保持。
4. 接单事务同时记录输入、幂等回执、调度意图和可发布事件。数据库确认前不对外说“已经接单”，网络超时不等于执行失败。
5. 租约到期不等于可以重做外部副作用。启动、恢复、重试、取消有持久 attempt 与所有权代号；迟到事件不能把新状态改回旧状态。
6. 权限来源不能是模型给的 `kind=system`、说明文字、环境变量或网页。默认 Agent 只能提出动作；程序核验身份、批准范围和实际参数。
7. 保留天启的现有功能、默认记忆隔离、网站、像素小芯、STM32 学习台、文件、登录、预算和免费资源。原有有效测试全部保留；记忆 v2 和重新开启学习记录另做。

## 设计调整（先定边界再搬代码）

### A. 唯一写者是切换协议，不是改几个 import

`poll/history/tasks/sessions` 都可能写观看标记、修复结束事件、调度任务；`memory_list` 可初始化/导入/建索引。先列出所有写者和副作用，再拆纯查询与状态命令。迁移期间可以逐个实现处理器，但**不能**让旧控制器直写、同时让新内核声称唯一写者。

引入版本化的所有权记录与独占进程锁。只保留用于所有权/部署互斥的一把 OS 锁，移除正常请求的跨进程业务锁。内核持有时，兼容 CLI 将状态请求转给本机内核；内核不在时返回可重试不可用，不能悄悄启动旧调度者。Worker 的 exec 降级在 kernel-owned 状态下也只能调用兼容客户端。

回滚目标必须是懂得所有权协议的“兼容桥版本”，不能任意启动 #136 的旧脚本。已运行的旧 runner/watchdog/每日任务/整理器先排空或完成桥接；**未经兼容测试，不热接管它们的进行中状态**。不要杀用户正在做的任务来获得空闲窗口。

### B. 状态与投影

保留 `documents/appends/commands/launches/handoffs` 与记忆/学习表，先加版本字段/新表，不删旧表列。内核读状态以 SQLite 为准，JSON/JSONL 是向旧客户端和回滚基线提供的投影，不再把投影修复当成提交本身。

投影有持久高水位，提交后可重建；投影失败时不能用旧 JSON 覆盖新状态。直接写文件的事件、统计、预算、存在标记、发件队列也要列入迁移，不能只搬 `StateJournal.write()`。暂不停止旧投影，不清理用户数据。

凭据、Cookie、内核认证密钥和 nonce 属于独立安全存储：不因为“只有一个状态库”的口号把秘密搬入可导出的工作流库。`kernel.sqlite` 的防重放状态可继续独立。

### C. 调度、进程与恢复

- 调度器只在提交之后启动执行器；启动意图落库，记录 attempt、执行器引用、租约、进程身份（boot id、pid/start、systemd unit）和事件位置。
- 内核重启先对照执行器是否真的还活着，再决定接管、恢复或标中断；不能看到过期租约就再起一份。
- 保留“每个执行任务一个 worker”的合理隔离，消除的是“每次 poll/HTTP 都一个控制器进程”。worker 只传事件、保留必要的未确认输出暂存，不直写业务库/用户状态。
- 不支持重新连接的 stdio app-server 不冒充可接管。适配器必须声明 `resume/steer/interrupt/reconnect` 等能力；不能重连就保留断点并安全中断，后续恢复要核对外部动作状态。
- `KillMode=process` 会留下子进程；改 `control-group` 又可能误杀执行器。将内核控制服务与每任务的执行单元分开管理，明确父进程死亡、停止和升级的所有权。
- 使用墙上时间检查截止时间；恢复后立即扫到期工作、断线流和执行器，不依赖暂停前的 setTimeout。
- 不能把旧 `spawnSync/flock`、编译、全项目哈希、打包、浏览器验收搬进 HTTP 事件循环。重工作交给执行进程，短事务只记阶段与结果。
- 所有 timer、流订阅、子进程、浏览器与退出钩子必须有 dispose。短命 runner 中原来可接受的 exit listener，在常驻进程中会累积；需要 soak 检查。

### D. 第二阶段必须有的安全地基

定义 `ExecutionContext`：可信发起者、模式、对话/任务/attempt、工作区、文件范围、站点引用、网络策略、授权引用。由内核根据可信请求创建，模型不能自报这些字段。

定义 `ActionRequest` / `Grant`：动作类型、规范化目标（路径/站点/服务/包名）、参数摘要、task/attempt、有效期、一次或任务范围、撤销/消费状态。确认 UI 直接回程序端；聊天里“批准了”、网页文字或后台自答不能生成 grant。先覆盖宿主执行和现有文件写回，不在这一步实现所有工具分类。

- 普通维护诊断仍可作为受限工具自主执行。安装软件、系统服务管理等经可信宿主 broker 执行，默认 Agent 没有直接访问服务控制、宿主 key 和免密 sudo 的路径。
- 需要一般 shell 的复杂维护，可以给用户明确展示后授予一次/任务范围的宽维护能力，不把批准一个文件删除解释为任意 shell 权限；能力扩大重新授权。
- 仅加提示词、改 `approvalPolicy` 或复用环境变量 `XIN_RUN` 不满足验收。应在 InstaBox 单机内验证不同 uid/命名空间与受限 sudo/独立服务的最小方案；用 Unix socket 的 OS 对端身份或沙盒不可替换的每次执行通道，不能信任消息体自报 uid/task。
- 将每日任务拆分为外部浏览/内容处理与确定性的宿主步骤，迁移前先核对清单需要的能力；保留已有自动化，沿用站长预先授权的任务范围，不能让网页为它增加宿主动作。
- 凭据通过窄 broker 使用；模型/任务进程只有引用，不能取得全部 Cookie。秘密持有服务必须确实处于普通任务不可读写的边界外，同 uid 的 0600 不是额外隔离。
- 天启保持用户主动选择的高信任执行域与功能；不由默认 Agent 的任务结果自动开启。保留 root 就不能承诺对天启强隔离，这个限制要写入文档和验收。

此处对现有宿主直接执行路径的替换属于重大变更：先做本地/临时数据 PoC 和兼容测试，再以单独 PR 提交；不借本轮只读连接权限去改生产用户、sudo 配置或钥匙。

### E. 网络与凭据策略的后续接口

第二阶段给每任务传递不可由模型扩大的网络策略，代理必须有检查入口、审计和拒绝路径。第三阶段补完整的动作授权和站点写操作。

公开资料任务：干净浏览、少量指定项目材料、公网访问。私人数据任务：授予必要数据和服务的读取权限，新增外发目标或连接器写操作走授权；明确用户主动选择的宽访问范围。文件 scope 与出站 scope 要一起考虑。

HTTPS CONNECT 只看目标地址，不能看明文方法/内容；仅靠域名名单不能阻止向允许的同站账号或页面泄漏。对于登录、上传、发消息等重要操作优先用受控连接器/浏览器接口；不引入全流量 TLS 解密、eBPF 污点系统或付费分类模型。

## 迁移与回滚操作顺序

1. 在空的临时目录/假网关完成全部演练。真实数据迁移随独立 PR 验证、备份并进入已授权的发布流程；本次不自行部署重大重构，不拿生产数据当故障测试样本。
2. `VACUUM INTO`/备份 API 做 SQLite 一致快照，并记录文件投影的高水位；不能只复制正在运行的 `.sqlite` 文件而丢 WAL。参考 [SQLite WAL](https://www.sqlite.org/wal.html) 与 [备份 API](https://www.sqlite.org/backup.html)。
3. 停止接受新本机启动意图，Cloudflare inbox 继续持久收消息；等待旧 writer/runner 安全退场，列出不可热迁移的等待确认/活跃任务，不强杀它们。
4. 在所有权锁内备份/迁移/检查，切换 owner，再恢复收件与调度。新字段只能向前兼容；每次迁移带版本和重复执行测试。
5. 回滚：进入排空模式→停止新派发→核对/接管或安全中断执行器→刷兼容投影→确认桥接器理解全部在途状态→释放所有权→启动 legacy bridge→恢复投递。
6. 无法映射的 kernel-only 状态必须在激活该功能前设计回译/中断策略并实测。不得因“不删表”就跳过这项，也不直接恢复旧备份覆盖迁移后新消息。
7. Cloudflare inbox 保留、clientId 不变；未送达不得因切换丢弃。exec 降级不能绕过 owner，SSE 降级仍只换读取通道。

## 验收矩阵（每批补相应行为用例）

| 情景 | 必须证明 |
|---|---|
| 接单提交前/后、派发前/后 kill -9 | 回滚或持久回执；输入不丢、不会双启动 |
| 内核死、执行器活；反过来；两者都死 | 按真实身份接管/恢复/中断，不因 lease 到期启动第二份 |
| SIGSTOP/CONT、墙钟前跳/后跳 | 复核绝对截止时间，不靠旧 timer；过期授权不能使用 |
| 临时实例暂停/恢复与冷启动 | 服务自启、时钟/HMAC 重试、免费冷却下消息持久等待；不能在生产电脑演练 |
| 响应丢失、重送、换传输、流断线 | 同 clientId 同结果，冲突拒绝，FIFO，事件不重复呈现 |
| 多会话/同项目并发；取消撞完成 | 通道和目录互斥；取消决定与结果状态一致 |
| SQLite busy/磁盘满/迁移中断 | 事务一致、幂等升级、清楚报错；恢复不以旧投影覆盖提交 |
| owner 切换中旧版本/旧 Worker 请求 | 拒绝或桥接，不出现第二写者和旧调度器 |
| 跨版本 rollback，含 waiting/publication/steer/handoff | 回译或明确中断；保留输入，不静默重做外部动作 |
| 恶意网页/文件声称用户批准、伪造 system/task/uid | 程序侧拒绝；真实用户按限定范围授权后仍可完成任务 |
| 凭据、重定向、私网 DNS、未知目的站点 | 无全量 Cookie/key 导出，无日志明文；策略不可由任务扩大 |
| 学习台、项目验收、记忆、每日任务、天启 | 原行为测试保留；天启仍有原功能，默认记忆不混入天启 |
| 多轮浏览器/模型调用、反复暂停恢复 soak | timer/listener/FD/内存稳定，清理不杀其他任务 |

每批必须 `npm run check`、`npm run test:e2e`、Actions。改页面另做 1280/1024/768/390、浅深色截图。故障测试只在临时目录/专用测试实例，以合成数据和假凭据运行；生产只做已授权只读核验。
