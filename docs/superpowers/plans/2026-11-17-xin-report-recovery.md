# 状态报告失联的恢复补丁

基线：main #164 / `21d7bdf`；Claude 的 #165 / `6c4025c` 仍是独立的 Worker 回程延迟修复，本补丁不接管其分支、不改工作台界面。问题发现：Claude Code；独立复现、实现和回归：Codex；复核责任及最终验证结果记在本批 PR 和交接记录。

## 问题与范围

真实临时套接字在收完请求、处理前暂停 owner，再杀掉并重起，可稳定复现两种失败：`front_immediate` 抛错退出 runner 主流程，但 300ms 桥定时器仍保持进程和生命周期锁；`front_model` 抛错则在模型调用前就失败收尾。仅给定时器 `unref` 不能修复后一种。另一个隔离探针证明 `agy_conversation` 已提交、回应丢失时会误换 Codex；它是可复现的失败类别，尚不能断言是每一次历史 CI 偶发失败的原因。

只修报告恢复边界，不重试模型调用、shell 或任意业务操作。完整持久收尾和输入交付继续依照 [3B 后续计划](2026-11-16-xin-finalization.md)。

## 实施顺序与行为保证

1. 先保留 main #164 的失败证据，再加入临时目录中的真实 owner/socket 故障回归；不增加线上故障接口，不在正式电脑杀进程。
2. `retryLockedReport` 明确只允许 `front_immediate`、`front_model`、`agy_conversation` 对已送出但结果未知的传输失败重试。前者沿用 `.front.json` 和 `task.frontRun` 去重；后两者是受当前 run/attempt 约束的相同值赋值。每次仍重新判断所有权，业务拒绝、协议错误和过期尝试不当成传输故障。
3. `requestStateSync` 对 write、append 和审过的 19 个具名状态操作固定一次逻辑调用的请求编号和正文。利用现有 SQLite `bridge:<id>` 事务回执返回原结果，不因断线生成新编号；任意 op、xin 或未来新增 named 默认不自动重放。未知后再遇连接拒绝，最终仍保留 unknown，防止外层换编号重做。
4. 重试等待和 owner RPC 共用单调 30 秒预算，并把剩余预算交给单次 RPC；helper 退出另有原有 3 秒宽限。若期间切回 legacy，所有权检查与本地 flock 仍按原有上限等待（tasks 最多 20 秒、普通锁 3 秒），本地操作也沿用原生命周期，因此不把整个函数承诺成严格 30+3 秒。长期失联后明确失败，不能据此宣称产出已经持久保管。辅助桥定时器不独自保持已失败的执行进程存活；实际执行器和等待流程照常维持自身生命周期。
5. 新派发进程的启动健康探测也是只读操作：完整帧后 owner 死亡时，异步等待恢复而不是单次 3 秒失败就退出。共用单调 30 秒上限、每次 RPC 至多 3 秒；仅专用 health，不接受任意操作，不阻塞进程事件循环。
6. `agy_quota` / `front_quota` 不加入重放名单：现有采样直接追加文件，重送会重复采样。后台 Antigravity 首次额度读取与报告分开，只对已知传输异常保留刚读取且校验过的额度结果。真实额度耗尽仍阻止工作，查询失败/畸形仍拒绝，非传输错误仍暴露。此处不承诺丢失的采样自动补送。

## 验收与发布

- 前台准备/模型选择：完整请求送出后、处理前 owner 死亡；原尝试恢复、成功收尾、模型恰好调用一次。
- 视觉转交：任务已提交后丢回应；只有一个任务、同一尝试、聊天模型不调用，后台执行器正常启动一次。
- Gemini 会话/额度报告：已提交后丢回应，同一个 Gemini 接着 note、note、final，不换执行器、不重复动作；额度采样不自动重放。
- SQLite append 和非幂等 named：丢 ACK 重送仍只有一次副作用；同 ID 换内容冲突；持久失联和协议错误有界退出。
- 新派发进程的启动 health 完整帧后 owner 死亡：原尝试接着启动，模型只一次；协议错误与永久失联有界拒绝。
- 非重试初始化失败时 runner 退出，避免只测成功重试掩盖定时器挂住；仅在临时副本恢复 ref 的反向验证必须失败。
- 保留原 check、真实内核模式、13 组 E2E、尝试隔离/停止/旧模式切换与队列回滚回归。不放宽原预算或过滤异常 ACP 让断言变绿。

本地完整通过、独立复核后创建 PR；CI、测试站和冒烟全绿后核对 main/head 再合并。正式 Actions 与真实模型联调成功、回滚跳过，最后只读核对实际模块摘要和单 owner；不能以本地通过替代上线证据。准确结果以 PR/交接的当前记录为准。

## 迁移、回滚和未完成项

无 schema、队列格式或用户数据迁移，不变更凭据和宿主权限。正常发版排空并替换 owner；已有 runner 保持其原版本，不能声称热替换了旧执行器。回滚到已正式验证的 #164 或后续兼容版，不恢复旧数据库；回滚会恢复本补丁修掉的失联缺陷。队列默认开启的最低读取方仍为支持 note 的 #162 / `c421176`，更早版本要先排空。

尚未实现：终态包持久化、长失联后的完成结果投递、`steer_take` 未知交付重送、原生 task_note 回调的持久 ACK、项目发布的可恢复阶段、统计/采样统一入事务。宿主授权 C、独立凭据代理及工具权限不在本批实现，也不因本补丁减少电脑维护、浏览器、天启或学习台能力。

参考：[Node.js timers.unref](https://github.com/nodejs/node/blob/v22.x/doc/api/timers.md)、[process.exitCode / 避免强退截断 I/O](https://github.com/nodejs/node/blob/v22.x/doc/api/process.md)、[Temporal 的持久请求去重](https://github.com/temporalio/temporal/blob/main/service/history/api/respondactivitytaskcompleted/api.go)、本项目既有 SQLite 命令回执。未引入这些项目的服务或新依赖。
