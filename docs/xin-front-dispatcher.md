# 小芯前台纯调度模式

## 边界与调用链

只改变默认模式（会话记录仍以 `agent: codex` 标记，兼容原 API）。前台不再启动 Codex CLI / app-server，不走它们的 shell、MCP、浏览器或文件编辑工具；由 Node 控制器直接调用现有网关的 Responses API，固定 `deepseek-v4.1-flash`，只注册一个结构化 `xin` 函数。

`send → runner → runtime.frontTurn → front_action（tasks 锁）→ 现有 taskNew/taskTell/...`。

允许的参数是 `['xin','task', 'new|list|show|tell|stop', ...]` 或 `['xin','remember', ...]`。它们被当作数据解析，从不交给 shell，不靠 PATH 或命令字符串前缀判断。`bash -c`、管道、重定向、文件/MCP工具及未知工具没有执行入口。show/tell/stop/after 限定本对话；网关错误不回退其它前台模型，不回退旧的全权限 CLI，`XIN_CODEX_TRANSPORT=exec` 也不能恢复前台执行能力。

控制器本身仍可写记忆/任务记录、调度后台并持有网关凭据。这不是把控制器放入 OS 沙箱；拥有宿主代码执行能力的人仍可改代码/记录，故不能把这个边界当成防宿主入侵的隔离措施。后台沿用原有隔离实现。

## 一轮的预算和连续对话

- 最多 3 次结构化工具调用，推理请求总预算 25 秒；new/tell/stop 成功后立即用固定第一人称短句结束，不等待后台完成，不再给模型一次自由执行机会。
- 超预算且未做过修改时，明确的工作保存用户本轮原话、网页上下文与近期对话派后台；普通聊天超时明确报错，不制造假任务。如果已有未完工作而不能确定对应关系，先问清，不把含糊指令加到任意工作，也不重复新建。
- 同轮修改记录保存在 `<run>.front.json`，新任务另存 `frontRun`，预算回退与重放避免重复建任务。tell 与记事不是事务型 exactly-once（崩溃窗口见下）。
- 后续请求通过原任务 tell 继续，等待问题用原有 ask/tell。进行中/等待/完成摘要每轮注入，详细进度只能查询真实状态；不把运行多久等同于完成比例。
- 前台上下文取最近 12 轮网页对话，每条最多 12000 字，长期记忆另带；不再使用旧 CLI rollout 续聊。此处未增加自动长期摘要。
- 用户点名记录到 `frontNamed`，覆盖新工作模型；首次明确点名做网页且无显式调度参数时直接走接单路径，无须等待一次前台推理。后台 `strictModel` 只允许原模型重试一次，禁止静默 fallback，保留 requested/actual 记录。图片交后台 vision；原有模型能力校验与独立复核限制仍有效，点名不能绕过。
- 简短进度问句由控制器直接读取本对话真实工作状态：排队、制作、实际浏览器检查、失败或已完成。成功网页附已发布链接，不把工具接受请求当成完成。

## 网页成品

`你让 Kimi 去画个奶龙 → 接单 → Kimi 后台 task new --web → 写 HTML/xin-web.json → 生产进程全部退出 → 容器内 Chromium 实际点击 → 不可变快照 → 我画好了 + 预览按钮`。制作期间前台保持 DeepSeek，可继续聊天。

网页使用 CSS/内联 SVG/Canvas 与内联脚本，不依赖 CDN、网络接口、多文件资源或常驻端口。根目录 `xin-web.json` 指定 HTML entry、title 和 1–8 条点击检查（selector、expectSelector，以及 expectText/expectClass/expectAttribute）。控制器另起真实 Chromium 检查 1280/390 宽度、内容可见性、标题、横向溢出、页面错误及点击前后变化；失败交回原任务修正，最多两次，不用模型口头声称的测试作证据。

发布时再次校验最终 HTML 摘要，将 HTML、PNG 截图和文件摘要写入 `~/.xin/previews/<随机ID>/` 后原子发布。只在对应本轮检查通过并发布后返回 ready 链接；修改原稿或清理 tmp 不影响旧作品。没有自动删除作品或用户历史。

`/xin/preview.html?id=…` 是可信包装页，需登录才能读取专用快照接口。包装页等待电脑唤醒、处理登录失效、支持下载。HTML 在不含 allow-same-origin 的 iframe 中加载，响应与内联 CSP 禁止网络、表单、嵌套框架和站长 API；专用接口核对固定控制目录路径、长度与 SHA256。原有通用文件接口仍为附件下载。

## 对外呈现

默认聊天、任务卡片、工作中心与推送使用“我在做”“我弄好了”“我需要你确认”。不主动展示模型/编号/分身；默认模式不再显示实际模型脚注或模型统计，API 与 model-stats 不删改。天启模式仍保留其模型选择与诊断。去掉“装作不知道”的身份提醒：直接问实现时如实简短回答，不编造。

## 收尾与权限

后台每轮结束先清理并确认整个原任务 session 已无存活生产进程，再做构建/网页检查、发布和释放项目目录；检查浏览器及其端口由受限进程命名空间与超时共同回收。终态仅清理归属校验通过的 `xin-task-<sid>/tmp`。等待用户或待写回时不删临时目录，保留续接。网页快照不依赖临时服务；项目 work/output 不自动删除。既有 li 服务及其它工作不属于清理范围。

密码/验证码只能在正规登录页面由用户填写，不自建收集表单，不写进任务或记忆；删除/部署/支付等仍走现有明确确认。原后台网络隔离问题不在此次修改范围。

## 待验证与已知限制

1. 本地 mock 不作为真实联调证据：正式部署流程另跑真实 DeepSeek 聊天、Kimi 制作网页、原模型核验、实际点击和收尾检查，失败自动回滚。25 秒是前台推理预算；控制器锁、电脑唤醒和网络可能另有开销，不承诺所有请求秒回。
2. 后台原有容器不能自动获得宿主桌面/设备权限。浏览器登录或设备操作派出后，可能仍因后台能力不足而需单独设计受控执行器；不为达成表象重新给前台 shell。
3. “闲聊还是工作”“这句补充针对谁”、口吻与危险动作授权的语义判断仍依赖模型/原有审批逻辑。硬保证的是前台没有执行工具、结构化桥范围与预算，不是自然语言永不出错。
4. 同轮 new 的 frontRun 可覆盖任务保存后、修改回执保存前的崩溃窗口；tell/remember 的副作用与回执尚非同一事务，极端崩溃可能重复补充。用户跨轮重复说一件工作是否去重由会话语义决定。
5. 一轮先完成一个修改即返回；`--review` 是控制器额外创建依赖复核。多件独立工作需要后续轮次/进一步批量调度设计。复核安排失败会明确说明。
6. Harness/Claude 的执行链沿用原实现；共享的人设提醒、收尾和任务 UI 为一致性作调整。网页只交付自包含 HTML，常驻后端应用与外部服务的生命周期另需实现。
