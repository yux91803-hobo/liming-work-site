# 小芯前台纯调度模式

## 边界与调用链

只改变默认模式（会话记录仍以 `agent: codex` 标记，兼容原 API）。前台不再启动 Codex CLI / app-server，不走它们的 shell、MCP、浏览器或文件编辑工具；由 Node 控制器直接调用现有网关的 Responses API，固定 `deepseek-v4.1-flash`，只注册一个结构化 `xin` 函数。

`send → runner → runtime.frontTurn → front_action（tasks 锁）→ 现有 taskNew/taskTell/...`。

允许的参数是 `['xin','task', 'new|list|show|tell|stop', ...]` 或 `['xin','remember', ...]`。它们被当作数据解析，从不交给 shell，不靠 PATH 或命令字符串前缀判断。`bash -c`、管道、重定向、文件/MCP工具及未知工具没有执行入口。show/tell/stop/after 限定本对话；网关错误不回退其它前台模型，不回退旧的全权限 CLI，`XIN_CODEX_TRANSPORT=exec` 也不能恢复前台执行能力。

控制器本身仍可写记忆/任务记录、调度后台并持有网关凭据。这不是把控制器放入 OS 沙箱；拥有宿主代码执行能力的人仍可改代码/记录，故不能把这个边界当成防宿主入侵的隔离措施。后台沿用原有隔离实现。

## 一轮的预算和连续对话

- 最多 3 次结构化工具调用，推理请求总预算 25 秒；new/tell/stop 成功后立即用固定第一人称短句结束，不等待后台完成，不再给模型一次自由执行机会。
- 超预算且未做过修改时，保存用户本轮原话、网页上下文与近期对话派后台；如果已有未完工作而不能确定对应关系，先问清，不把含糊指令加到任意工作，也不重复新建。
- 同轮修改记录保存在 `<run>.front.json`，新任务另存 `frontRun`，预算回退与重放避免重复建任务。tell 与记事不是事务型 exactly-once（崩溃窗口见下）。
- 后续请求通过原任务 tell 继续，等待问题用原有 ask/tell。进行中/等待/完成摘要每轮注入，详细进度只能查询真实状态；不把运行多久等同于完成比例。
- 前台上下文取最近 12 轮网页对话，每条最多 12000 字，长期记忆另带；不再使用旧 CLI rollout 续聊。此处未增加自动长期摘要。
- 用户点名只记录到 `frontNamed`，覆盖新工作模型；后台保留 requested/actual/fallback 的真实记录。图片交后台 vision；原有模型能力校验与独立复核限制仍有效，点名不能绕过。

## 对外呈现

默认聊天、任务卡片、工作中心与推送使用“我在做”“我弄好了”“我需要你确认”。不主动展示模型/编号/分身；默认模式不再显示实际模型脚注或模型统计，API 与 model-stats 不删改。天启模式仍保留其模型选择与诊断。去掉“装作不知道”的身份提醒：直接问实现时如实简短回答，不编造。

## 收尾与权限

后台每轮结束清理自己启动的进程组（容器的 PID namespace 仍会回收容器内进程）；终态仅清理归属校验通过的 `xin-task-<sid>/tmp`。等待用户或待写回时不删临时目录，保留续接。项目 work/output 不做盲目秘密扫描或删除，未跟踪的外部资源只能由执行者按收尾指令关闭，失败须汇报。不会碰其它工作，也不会清理已有 li 服务。

密码/验证码只能在正规登录页面由用户填写，不自建收集表单，不写进任务或记忆；删除/部署/支付等仍走现有明确确认。原后台网络隔离问题不在此次修改范围。

## 待验证与已知限制

1. 本地 Responses mock + runner/浏览器回归，**不等于真实网关联调**。合并前应验证网关非流式 Responses、结构化 function-call、max effort 与 DeepSeek 的实际行为和延时；失败会明确报错而不是启用全权限前台。25 秒是上界，不承诺网络条件下“秒回”。控制器任务锁最多另等 20 秒，调度本身也有短暂开销。
2. 后台原有容器不能自动获得宿主桌面/设备权限。浏览器登录或设备操作派出后，可能仍因后台能力不足而需单独设计受控执行器；不为达成表象重新给前台 shell。
3. “闲聊还是工作”“这句补充针对谁”、口吻与危险动作授权的语义判断仍依赖模型/原有审批逻辑。硬保证的是前台没有执行工具、结构化桥范围与预算，不是自然语言永不出错。
4. 同轮 new 的 frontRun 可覆盖任务保存后、修改回执保存前的崩溃窗口；tell/remember 的副作用与回执尚非同一事务，极端崩溃可能重复补充。用户跨轮重复说一件工作是否去重由会话语义决定。
5. 一轮先完成一个修改即返回；`--review` 是控制器额外创建依赖复核。多件独立工作需要后续轮次/进一步批量调度设计。复核安排失败会明确说明。
6. Harness/Claude 的执行链不改；共享的人设提醒、收尾和任务 UI 为一致性作调整。没有合并、生产发布或 VM 操作。
