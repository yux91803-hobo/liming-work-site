# 小芯前台、可靠调度与完成事件

默认模式由固定 DeepSeek 前台和独立后台执行器组成。前台直接调用网关 Responses API，只注册结构化 xin 函数；没有 shell、文件编辑、MCP 或浏览器执行入口。后台继续使用现有 Codex app-server、容器、临时推理代理、STM32 强制构建与独立复核限制。

## 输入、事务和启动

`vm-state.mjs` 使用 Node 内置 SQLite（云电脑 Node 22.23.3 已验证），数据库在控制目录 `workflow.sqlite`，WAL + synchronous FULL，权限 0600，不映射给后台。新增表存储命令回执、JSON/JSONL 投影、执行启动意图和完成收件箱；旧 JSON 会话、任务索引和历史仍可读取，不自动删除或整体迁移用户记录。

带稳定 clientId 的输入按内容摘要去重。事务内保存输入、会话/任务变化、可见事件、启动意图与回执；提交并恢复投影后才启动执行器或发停止信号。提交前崩溃全部回滚，提交后崩溃由事务日志补全。相同标识不同内容明确拒绝，已完成请求复用原回执。

启动意图持久化，每轮另有生命周期 flock；实际 runner 自己登记 PID 身份。控制器崩溃留下的未启动工作可以补发，锁阻止重复执行。同一默认前台轮次中断后最多恢复一次，已有结构化修改回执和文字回复直接重放。后台恢复仍先清理旧进程树，再接断点；不能将逻辑超时当成进程已退出。

这些事务保证针对控制器记录和投递；外部网站、设备、发布等副作用仍需各自验证、权限与幂等策略。项目写回保留原有备份、冲突/删除决定及最终源码核验。

## 语义派工和模型

自然语言的制作、询问、否定、补充和停止交给前台推理，通过结构化参数调用 new/list/show/tell/stop。取消先前实验中的“奶龙关键词直接派工”路径；查询从真实任务快照或 show/list 取证。推理超过 25 秒或工具预算耗尽但没有确定操作时，保留输入并明确报错，不制造泛化任务。

前台固定 `deepseek-v4.1-flash` / max，用户点名只约束后台。明确点名的工作固定模型，入口未开始工作就失败时只按同模型重试一次，禁止静默 fallback；请求模型与实际模型分别记录。后续 tell 继续原工作及其模型约束。

前台上下文与展示聊天分开：持久保存近期上下文检查点和有来源的旧轮次检索索引，最近 12 轮保留原文窗口；更早细节用 `xin recall 关键词` 查询本对话原文。索引明确标记可能截断，不当作新事实或长期记忆。长期记事本独立保留。

## 完成后继续负责

后台结束时，任务记录和完成事件一起提交。事件绑定 task、所属对话和结果版本，重复事件只形成一个收件项。watchdog 和外部监督继续驱动，网页关闭也能处理。

完成处理以低于用户消息的优先级启动原 DeepSeek 前台。用户输入可以中断这轮内部汇报，先完成用户消息；旧回调和过期结果不能覆盖新要求。小芯按原要求与真实证据决定：继续原工作、正式交付或安静结束。失败与需确认必须如实告知。

完成汇报通过 finish_event 结构化决定，和内部过程、普通接单回执分开。交付文字、结果版本、通知出站项同事务提交；页面任务结果与保存的聊天消息合并为一条，刷新不重复。后台结果需要修正时只能继续对应原工作，不能重复创建；自动续接每项最多两次，完成推理最多两次失败后用已验证结果兜底交付。

执行启动按用户、完成事件、例行任务排列；前台与每件后台工作有独立轮次。后台仍由统一调度器派发，原生无限递归派工保持关闭，项目及嵌套目录继续串行保护。

## 预算

保持现有 max，不自动降低思考强度。每项工作默认最多 128 次推理请求及 150 万已报告输入加输出 token，跨续接与后台完成推理累计；可由控制器配置 XIN_TASK_REQUEST_LIMIT / XIN_TASK_TOKEN_LIMIT。缓存输入另记，不重复加到总数。没有提供 usage 的响应记为未知，不当作零消耗；这不是人民币费用限额或供应商账单。

## 网页成品

结构化 `xin task new --kind code --web` 生成自包含 HTML 和根目录 xin-web.json。CSS/JS 内联，绘图用 CSS、SVG 或 Canvas，不依赖 CDN、外部接口或常驻服务。清单指定 entry/title 和 1–8 个 selector 点击检查，结果用 expectText、expectClass 或 data/aria 属性表达。

生产进程全部退出后，控制器在容器里启动实际 Chromium，以 1280/390 宽度检查标题、内容、横向溢出、页面错误、真实点击及前后状态变化。失败最多返工两次，不能用模型口头声称测试代替检查。

通过后再次绑定最终 HTML 摘要，把 HTML、真实 PNG 和文件摘要原子发布到 `~/.xin/previews/<随机ID>/`。只有本轮通过检查并发布才返回 ready 链接。清理本任务进程与私有 tmp 后，旧作品快照仍可打开；没有定期删除用户作品。

`/xin/preview.html?id=…` 是可信包装页。专用接口需要站长认证，核对固定路径、长度与 SHA256；作品在 opaque iframe 中运行，CSP 禁止网络、站长 API、表单和嵌套框架。支持等待唤醒、重新登录、重载和离线 HTML 下载。通用文件接口继续按附件交付。

## 验证和来源

回归包括事务提交前/后崩溃、输入重发/摘要冲突、启动优先级、前台进程死亡、过期完成、用户打断汇报、自动返工预算、跨恢复 token 预算、结束清理和浏览器实际交互。正式部署另跑真实模型接单、同时聊天、关闭网页后完成、迟到响应切会话、Kimi 奶龙网页、自动交付与预览点击，失败自动回滚。

架构参考公开的 [0.18 重建项目](https://github.com/b-nnett/grok-bot-0.18-reconstructed)、[Harness 逆向解析](https://gist.github.com/gfsaaser24/9f785c0c095b693b31b5efbcbae7bcd0) 和 [Open-Grokbot](https://github.com/LING71671/open-grokbot)。本实现独立编写，参考队列、接单、完成唤回和恢复机制；没有将不同版本或重建者扩展视为当前 Grok Bot 的原样实现。
