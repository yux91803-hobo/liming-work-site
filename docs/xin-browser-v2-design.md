# 小芯浏览器第二步：用站长的登录（设计）

- 日期：北京时间 2026-11-12。
- 站长的话（2026-11-12）：「我目前想不到，网站太多了，都放开吧，我想让它登哪些他就登」。
  所以**不设网站白名单**，改成「站长在任务里点名哪个网站，就带哪个网站的登录」；`docs/xin-next-stage.md` 5.2 里「只在站长加入白名单的网站使用保存的登录」由这一条代替，5.3 的确认规则不变。
- 依据：`docs/xin-next-stage.md` 第 5 节、`docs/xin-browser-v1-design.md`（第一步，公开网页，已上线）。
- 这一步分两个 PR：
  - **本 PR（2a）**：保存登录、任务点名网站、登录交给站长（登录窗口）、设置里的「网站登录」。
  - **下一个 PR（2b）**：有后果的操作先发确认卡（附截图）、站长同意后同一个任务里放行一次。2b 之前，带登录的任务碰到付款、发送、删除这类按钮，照第一步一样拒绝，让模型写进结果。

## 1. 参考

- **Nanobrowser** `src/browser-control/core/interaction/gate.ts`、`src/agent/loop.ts`：
  - 往密码、卡号、验证码框里输入，付款、授权，都是「用户的这一步」（USER_STEP）：什么都不发，把这一步交给用户；
  - 用户做完点「交还」，模型拿到新的页面快照；用户取消，告诉模型「别换别的办法做，问用户或者收尾」。
  - 提交、删除、上传另走确认卡。小芯照这个分：登录交给站长（本 PR），有后果的操作走确认卡（2b）。
- **Browser Use** `browser_use/domains.py`：
  - `allowed_domains` 用 CDP `Fetch` 拦主框架的文档请求，标 `BlockedByClient`；每步之后再查一遍标签页，停在不许的网站就清掉。
  - 它自己写明「这是给听话的模型的护栏，不是沙盒」：子资源不拦，模型自己的网络也不归它管。
- **Playwright MCP** README：
  - 一份持久资料同时只能给一个浏览器用；要并行就用 `--isolated` 加 `--storage-state`，每次把保存的 cookie 装进一个干净的浏览器。
  - 小芯照后一种做：登录按网站存成文件，每轮只装点名网站的那几份。
- **OpenAI Operator**（公开的 system card / 帮助页，不开源）：
  - 输密码、付款时进「接管模式」，用户自己在浏览器里输，代理不看；
  - 登录状态会保存，用户能在设置里看到、删掉。
- 小芯自己已有的：
  - 第一步的浏览器代理（`vm-browser.mjs`）；
  - 「屏幕 / 接管」（`openScreen`）；
  - 任务「等你确认」和推送（`xin task ask` → `pendingQuestion` → `taskFinish`）。

## 2. 结构

```
站长：「去 B 站看看我收藏夹里…」
  前台：xin task new --site bilibili.com …            → 任务记下 sites = [bilibili.com]
  后台这一轮：浏览器代理起一个干净浏览器，只装 bilibili.com 保存的 cookie；主页面只能在 bilibili.com 里跳
    └─ 没登录 / 要输密码 → 代理把这一步交给站长（不填、不点），任务停成「等你登录」，推送给站长
站长点「打开登录窗口」→ 小芯的屏幕（接管）上开一个登录窗口（没有模型，只有站长在操作）→ 自己输密码、扫码
站长点「好了，接着做」 → 登录窗口关掉，cookie 存进 ~/.xin/browser-logins/bilibili.com.json → 任务接着做，这回浏览器带着登录
```

## 3. 保存的登录

- 一个网站一个文件：`~/.xin/browser-logins/<网站>.json`。目录 700、文件 600，只有控制器读写，不挂进容器，模型拿不到。
  - 内容是 CDP `Storage.getCookies` 拿到的 cookie（含 httpOnly、只在会话期间有效的那种）和保存时间。
  - 不进机外备份（备份恢复后重新登一次就行）。
- 「网站」= 可注册域名：`passport.bilibili.com` → `bilibili.com`，`www.lcsc.com.cn` → `lcsc.com.cn`。
  - 用一小张多段后缀表：`com.cn`、`net.cn`、`org.cn`、`gov.cn`、`edu.cn`、`com.hk`、`co.uk`、`co.jp` 等；
  - `github.io` 这种托管域名按下一级算。
  - IP 地址不算网站。
- cookie 按它的域名归到网站。登录窗口里**主页面去过**的网站才保存，比如经 QQ 登 B 站时也存 `qq.com`；广告、统计这些只在子请求里出现的不存。
- 只存 cookie。少数把登录放在 localStorage / IndexedDB 里的网站记不住，每轮都要重新登。以后真遇到再加（Playwright 的 storageState 做法）。

## 4. 任务点名网站

- `xin task new … --site bilibili.com`（可以写多个，最多 5 个）：前台在站长要用自己账号做事时加（看订单、收藏、消息、发东西……），只按站长原话，不自己加。
- 站长在卡片上同意（见第 6 节）也会把那个网站加进这个任务。
- 任务卡片上写「用你的登录：bilibili.com」。

## 5. 带登录的一轮浏览器

- 只要任务点名了网站，这一轮的浏览器就是「带登录」的：
  - **装 cookie**：浏览器起来后用 `Storage.setCookies` 装点名网站保存的 cookie；别的网站的登录一概不装。
  - **主页面只能在点名网站里**：`open` 先查；每个页面开 `Fetch`，拦主框架去别的网站的文档请求（Browser Use 的做法）；每个命令之后再查一遍所有标签页，跑到别处的关掉。
    - 拒绝时告诉模型：「这一轮带着站长的登录，只能在 X 里浏览；公开资料用 curl / read_url_content 查，或者让站长在任务里加网站」。
  - **cookie 写回**：每个命令之后（至多 10 秒一次）把点名网站的 cookie 写回文件，网站续期的登录不丢；进程被杀也不怕。
- 没点名网站的任务照第一步：干净浏览器，哪儿都能去，没有任何登录。

## 6. 登录交给站长

- 触发：
  - 往密码 / 卡号 / 验证码框里填；
  - 点名字是「登录 / 登入 / sign in / log in」的按钮或链接；
  - 在登录表单里按回车；
  - 模型自己 `xin browser login [网站]`（不写网站就是当前页面的网站）。
- 代理不填、不点，用回调告诉控制器，控制器在任务上记 `browserStep = {kind:'login', site, url, saved}`，同时照 `xin task ask` 记一个问题。
  - 回给模型：「这一步是登录，要站长自己来：已经请站长登录 X。现在结束这一轮，最后一条写清楚做到哪了；站长登好后会接着叫你，那时浏览器已经带着 X 的登录。」
  - 模型不结束也没关系：同一个网站的登录这一轮不会再起作用。
- 这一轮结束 → 任务「等你确认」→ 推送「我这边需要你登录：任务标题」。
- 卡片三个按钮：
  - **打开登录窗口**：Worker 先开桌面，云电脑在桌面上开登录窗口（见第 7 节），网页打开小芯的屏幕（接管）。
  - **好了，接着做**：关登录窗口、存 cookie，把网站加进任务，任务接着做，给模型的话是「站长同意用 X 的登录（这一轮浏览器已经带上），接着做」。
    - 站长其实没登的话，下一轮还会再碰到登录，再问一次。
  - **不用了**：任务接着做，给模型的话是「站长不用 X 的登录。别换别的办法登录；做不了的部分写进结果」。
  - 也可以不点按钮直接回一句话：当成普通回复，这一步作废。
- 已经保存过登录、只是任务没点名这个网站（模型自己要用）时，卡片说「任务想用你在 X 的登录（之前登过）」，按钮一样：「好了，接着做」就是允许。模型自己不能把网站加进任务，必须站长点。

## 7. 登录窗口

- 云电脑上一个单独的进程（`node vm-agent.mjs login-window`，脱离 Worker 那次调用）：
  - Chromium 开在桌面上，必须有沙盒，必须走出网代理（只放行公网 80/443）；
  - 干净资料，装上这个网站已保存的 cookie，打开要登录的网址。
  - 里面**没有模型**，只有站长在屏幕上操作；它也不能接到任务的容器上。
- 同一时间只开一个：再开新的，先把旧的存好关掉。
- 结束：站长点「好了，接着做」或设置里的「登好了」、站长把窗口关了、开着超过 20 分钟。
  - 结束时把主页面去过的网站的 cookie 分网站存好，关浏览器、删资料目录。
  - 「好了，接着做」要等它存完（最多 10 秒）再让任务接着做。
- 屏幕链接照旧：接管链接 15 分钟内有效，关掉屏幕时作废。

## 8. 设置里的「网站登录」

- 列出保存了登录的网站和保存时间；每个网站一个「删掉」：只删云电脑上保存的 cookie，网站那边的登录设备要站长自己去网站上退。
- 「登录新网站」：填网址 → 打开登录窗口（屏幕接管）→ 登好后点「登好了」。先登好，以后任务点名这个网站就直接带上。

## 9. 提示词

- 前台（派任务的说明）：站长要用自己的账号在某个网站上做事时，加 `--site 域名`；只写站长说到的网站。
- 后台（浏览器说明）：
  - 这一轮带哪些网站的登录、只能在这些网站里浏览；
  - 要登录就 `xin browser login`，然后结束这一轮；
  - 密码、验证码永远由站长自己输入；
  - 付款、发送、删除这类还是不做，写进结果（2b 以后会有确认卡）。

## 10. 测试

单元测试用真的 Chromium、测试服务器上的两个「网站」（用不同的主机名指到本机，测试参数里放行）：

- 网站归属：`siteOf` 各种主机名（多段后缀、托管域名、IP、带端口）。
- 登录存储：存、读、删、只取点名网站的 cookie；文件权限 600。
- 带登录的一轮：
  - 起来时装上 cookie，页面看得到登录状态；
  - 跳去别的网站（`open`、点链接、表单提交、新窗口）都被拦；
  - 命令之后 cookie 写回文件。
- 登录交给站长：填密码框、点「登录」、在登录表单里回车、`xin browser login`，都不发到页面，回调收到正确的网站和网址，模型拿到「结束这一轮」。
- 没点名网站的任务：和第一步一样，不装任何 cookie，也不限网站。
- 登录窗口：起来时装上已有 cookie；页面上设的 cookie 在「结束」后分网站存好；只存主页面去过的网站；同一时间只一个；超时自己关。
- 控制器：
  - `--site` 解析和规范化；
  - `task_browser_step` 让任务停成等你登录；
  - 「好了，接着做」把网站加进任务、新一轮带上登录；「不用了」不加；
  - 回一句话当普通回复。
- 浏览器端到端（e2e）：任务卡片的三个按钮、设置里的「网站登录」列表和删掉（模拟器）。

## 11. 不在这一步

- 有后果的操作的确认卡、任务内授权、已执行动作账本（2b）。
- localStorage / IndexedDB 里的登录。
- 每日任务（签到）改用浏览器：现在仍是桌面操作，以后换。
- 自动填密码：密码、验证码永远由站长自己输入（`docs/xin-next-stage.md` 第 2 节）。
