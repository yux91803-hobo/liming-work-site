# 小芯代码复核修复

本轮按用户报告的 P0、P1、P2 六个问题逐项处理，原有上线验收不能替代这些边界攻击测试。

## 1. 桥接软链接越界与 TOCTOU

已修复：先打开且固定 io 目录 fd，所有目录项操作通过 `/proc/self/fd/<fd>` 完成；请求以 O_NOFOLLOW / O_NONBLOCK 打开，fstat 与限量读取使用同一个 fd。已有回复条目直接拒绝；在同目录用 O_EXCL / O_NOFOLLOW 独占创建随机临时文件，权限 0600，只写打开的 fd，写完用不覆盖目标的原子 hard link 发布。目录路径被替换也不改变操作所用 inode；客户端不会先读到预留的空回复。

攻击回归包括：恶意 reply 软链接、请求验证后替换、io 路径替换、打开请求后换文件。旧实现四项均失败，新实现四项均通过；另有真实并行客户端验证只看见完整回复。真实 bwrap 容器中预建指向控制器测试文件的 reply 软链接，控制器未执行该请求，也未修改测试文件。攻击目标全部是专用测试文件。

## 2. 发送途中切换对话

切换或新建对话统一递增 conversation generation 和 loadSeq。发送、轮询、停止、立即补充及历史加载的成功、错误和进度回调都核对所属代次；迟到响应不能修改当前 sid、run、消息或输入框。已提交给服务端的旧消息仍保存在原对话；旧队列只按原消息编号结算。失败的未提交消息保留为可恢复草稿，重试沿用 clientId，避免丢消息或重复提交。

浏览器回归覆盖迟到成功切新对话、切另一对话、迟到失败、切换后已发送新一轮、迟到历史，以及从通知/链接切换时旧队列仍归原会话，不能发进目标对话。正式站联调新增真实服务端响应延迟场景：A 请求已实际提交后拦住返回，切新对话，再放行并发送 B；页面须留在 B，A 的真实回复须可从 A 历史找到。

## 3. 快速答复重复提问

在 tasks 锁内把答复加入 inbox 时，同步消费对应 pendingQuestion；恢复为运行状态。一轮结束时优先保留随后新问的问题，避免旧 inbox 清掉新问题。回归使用真实 runner 和可控 CLI，覆盖快速答复后续接完成、不重复 waiting，以及答复之后又问新问题。

## 4. 独立复核模型硬约束

review 的 avoid 为硬约束，点名同作者明确返回“不属于独立复核”，全部候选耗尽则报错或等待；不会退回被排除模型。启动前、每次重试前按依赖任务实际模型重新核对，并在模型切换时锁内更新实际模型。记录 requestedModel、actualModel 与跨轮实际模型集合，复核避开所有实际参与作者模型；尚未干活就失败的预选模型不算作者。

回归覆盖视觉候选耗尽、点名作者、原任务 GLM 失败改用 Kimi 后，复核 DeepSeek 失败也仍避开 Kimi。请求模型与实际模型分别保留，不把“不同请求”误当成“不同实际作者”。

## 6. 非标准 STM32 工程的编译核验

从原项目、用户要求及递归源码/配置识别 STM32，并把原始识别结果留在控制器记录，删除副本标记不能绕过。支持根目录或唯一嵌套的 Make/CMake 入口；多个入口或不支持的结构明确失败。根目录 xin-build.json 可指定 system、directory、artifacts，以及 CMake 的 toolchain/preset；所有路径必须留在任务副本。云电脑安装脚本包含 CMake。

控制器在容器内重新构建，接受本次生成的有效 Intel HEX、ARM 32 位 ELF 或非空 BIN；不固定要求 build/app.hex。证据绑定最终源码与构建配置摘要；旧文件、错误 ELF、软链接输出都不能作成功证据。回归覆盖 Core/Src、嵌套入口、CMake、歧义、越界和旧产物。真实 ARM 工具链已验证嵌套 Make 与自定义 HEX 路径，以及 CMake/toolchain 工程生成 ARM ELF 与自定义 HEX，三者源码摘要均核对一致。

## 7. 组长退出后的进程清理

spawn 时记录 boot/start/group/session。清理扫描任务原 session 中的全部存活进程，包含组长先死、孙进程更换进程组；对照身份后用 pidfd 发信号，避免 PID 复用。TERM 后继续占用项目目录，必要时 KILL，确认残留清空再恢复或释放。运行时安装前检查 Python pidfd 支持。

故障注入覆盖组长退出、孙进程忽略 TERM，以及孙进程 setpgid；两种情况下目录保持占用，升级 KILL 后才收尾。真实云电脑重复了这两种故障，并额外通过实际 sudo/bwrap 容器的进程清理，验证 pidfd 和非交互提权重试可用。生产后台另有 PID namespace，容器 init 退出由内核清除该 namespace 的进程。

## 验证边界

这些回归验证指定攻击和竞态，不代表已证明不存在其他缺陷。编译成功不等于物理开发板通过，当前没有上板验证。发布仍要求完整单元、浏览器、测试站和正式站真实模型联调通过；具体运行编号与最终线上版本写入本轮验收记录。
