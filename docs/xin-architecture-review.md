见下面的问题清单：Bug 是 1、2、12、17；性能是 4、6、7；耦合和重复是 13、14、20。当前数据量下没有测到已经发生的性能瓶颈，6 是随历史增长的趋势问题。

### 问题清单（按优先级）

P1 影响日常使用或记忆的可信度，建议先做；P2 是有明确后果但不急的；P3 是清理和小修。没有 P0。

#### 01 · P1 · 前台会把整轮对话从上下文里删掉

现象

一轮里只要有一条消息被判为「敏感」，这一轮你说的和小芯答的都不再给前台模型看。判定很宽：任何 32 位以上的字母数字串（提交哈希、UUID、预览链接里的 ID、长宏名、一行 32 个减号）都算密钥；「焦虑、医院、工资、股票」等词算个人敏感。小芯交付网页时自己说的「我画好了。\[打开预览\]…」也因为带 32 位 ID 被删。

证据

`vm-memory.mjs:83-89 SECRET_VALUE / PERSONAL / memorySensitivity` · `vm-context.mjs:18-25 safeContextEvents`（第 23 行整轮返回空）· `vm-agent.mjs:692` · `vm-handoff.mjs:18 publicCompletion`

验证

已复现：三轮对话里第二轮带「有点焦虑」，第三轮前台只看得到第一轮。

建议

上下文这一层只处理真正像凭据的值，并且打码那一段而不是丢整轮；预览链接、哈希、UUID 排除；个人敏感词只限制记忆归纳，不影响当前对话。

#### 02 · P1 · 前台能把你没说过的话记成「你明确说的」

现象

前台模型调 `xin remember --basis stated` 时，控制器直接存为生效记忆，出处填的是这一轮你的整句话，不检查内容对不对得上。完成事件那一轮（前台在读后台任务的结果，没有你的话）也能这样记，等于网页内容经后台任务可以间接写进你的个人画像。这和设计里「每条记忆必须引用原话并逐字核对」不一致。

证据

`vm-agent.mjs:2461-2479 companionCmd`、`1738 frontAction` · `vm-memory.mjs:178 addMemory` · 对照 `vm-memory-idle.mjs:107-119 verifiedEvidence` · `docs/xin-next-stage.md §4.6、§4.7`

验证

已复现：你说「那开漏呢」，模型记「兄弟是做电机控制的工程师」，结果状态是生效、依据是明说、出处是「那开漏呢」。

建议

stated 要求模型给出引文，并且引文逐字出现在本轮你的原话里，否则降为待确认；没有用户消息的轮次（完成事件）禁止 remember。

#### 03 · P1 · 三条完全放权的路径能直接改记忆、读密钥、改控制器

现象

天启、Claude 旧模式、每日任务都和控制器是同一个用户。其中每日任务风险最高：它每天自动上网签到，不进容器，设定里带着你的记忆，工作目录是整个 WORK，电脑自带的桌面操作和云电脑管理插件一直开着。控制器脚本按文件名里的哈希执行，但执行前不核对内容，被改了不会发现。

证据

`vm-agent.mjs:2486-2489 xinCmd`（守卫只看 XIN_RUN）、`1395`（`sandbox: !t.dailyDate`）、`1345`、`405`、`412`、`875`、`395`、`318-323 harnessEnv` · `vm-memory.mjs:331-333 coreMemory` · `src/xin.js:165-185 exec`

验证

已复现：带 XIN_RUN 时天启被拒绝；同一个 shell 里 `env -u XIN_RUN xin remember --basis stated …` 写入成功，记忆页显示为生效；`xin bond +3` 也成功。

建议

先做方案 B（启动自检脚本哈希、记录越界）；每日任务在浏览器 v1 之前至少放进带出网代理的容器，设定里不带个人记忆；接口不再接受新建 Claude 会话。方案 B 和每日任务进容器需要你点头。

#### 04 · P2 · 全局任务锁和数据库写事务里做重活

现象

任务收尾时的校验、哈希、写回、发布预览，以及任务开工时复制整个项目（上限 150 MB），都在全局 `tasks` 锁和一个 SQLite 写事务里做。其他请求等这把锁最多 20 秒，等数据库最多 15 秒；而每个控制器进程一启动就要拿一次写锁。项目大时，发消息和轮询会报「上一句还没做完」或直接出错。

证据

`vm-agent.mjs:2564-2581 transactionalOp`、`1453-1472 taskFinish`、`1388 startTask`、`237 lockedCall`、`2516 main` · `vm-runtime.mjs:34-48 prepareWorkspace`、`66-74` · `vm-state.mjs:17`、`72`

验证

读代码得出，没有用大项目实测耗时。

建议

锁外先算好计划和哈希，锁内只做核对和状态提交。

#### 05 · P2 · 删掉对话后还留着内容

现象

删除对话会清掉对话记录、事件、Codex 会话和状态库里的大部分副本，但这些还在：发送回执（含标题，也就是你第一句话的前 40 个字）和它在状态库里的那一行、通知队列里的结果正文、`/tmp/xin-task-…` 里的项目副本和任务自己的 Codex 会话、预算和工作区清单、写回备份、预览、以及桌面终端日志里的原话（天启的也在）。

证据

`vm-agent.mjs:2055-2075 forget`、`2266-2278 task_drop`、`1885-1889`、`1936`、`202-208`、`260 emit` · `vm-state.mjs:107-116 dropConversation` · `vm-runtime.mjs:36`、`422`、`636-642` · `vm-screen.mjs:27-28`

验证

读代码得出。

建议

给 forget 一份统一的清理清单；任务结束并写回后删掉 /tmp 里的副本。这属于删数据的改动，动手前我会先把清单给你看。

#### 06 · P2 · 若干操作的开销随历史线性增长，没有上限

现象

现在不是瓶颈，但会越来越慢：每次调用都起一个 node 进程；每个进程启动都全表扫描状态库找未投影的行；轮询每次读整份事件文件；对话列表每次读全部会话文件；你每发一句话都要遍历所有对话的所有轮次来同步检索索引；空闲整理期间每 250 毫秒读一遍所有轮次的元数据。保留期没做，所以这些只增不减。

证据

`vm-state.mjs:22-23`、`74`、`80` · `vm-agent.mjs:2115`、`2134` · `vm-context.mjs:26-50`、`76` · `vm-memory-idle.mjs:34-39`、`205`

验证

已测：本机每次调用约 0.11 秒，带锁的约 0.17 秒；状态库在 2 千轮时每次启动扫描 6 毫秒，2 万轮时 64 毫秒、库 146 MB。

建议

给 `dirty=1` 和 `projected=0` 加部分索引；轮询按字节偏移读；忙闲判断只查 launches 和 handoffs 表；检索同步按对话的更新时间增量做。

#### 07 · P2 · 前台系统提示每分钟都在变，缓存用不上

现象

前台的系统提示里嵌了当前时间（精确到分钟）、每日任务记录和记忆正文，所以每分钟、每次记忆变化都会让前缀缓存失效。Opus 那条路每轮新开一个会话，把设定和全部历史重发一遍。设计文档写的是「不改系统提示以保持缓存」。

证据

`vm-persona.mjs:64-78 systemPrompt` · `vm-daily.mjs:28-36 dailyContext` · `vm-front-opus.mjs:77-86`、`158` · `docs/xin-next-stage.md §4.5`

验证

读代码得出，没有对比网关的缓存命中数据。

建议

时间和每日记录移到本轮输入的末尾，系统提示只留不变的规则。

#### 08 · P2 · 记忆库只有一份，没有导出和备份

记忆、学习画像、对话索引都在云电脑的一个 SQLite 文件里。版本表在同一个文件里，文件丢了就都没了。仓库里没有任何导出或备份代码；正式站回滚也不回滚云电脑数据。

建议

每天导出一份（`VACUUM INTO`），加密后放到云电脑之外。放哪里需要你定。

#### 10 · P2 · 正式站密钥经过一台共享的自托管执行机

检查、测试和部署都跑在标签为 `box` 的自托管机器上。部署步骤把 Cloudflare 令牌、站长密码、InstaBox key 交给那台机器上的进程。它的说明里写着：网络共享，机器上另有一个带免密 sudo 的普通用户。另外，正式站是先上线再做真机联调，失败才回滚，窗口最长约 35 分钟。

证据

`deploy.yml:53`、`82`、`150`、`253-283`、`314-332` · `scripts/box-runner/README.md`（Isolation / credentials 一节）

读配置得出。

带密钥的部署和联调步骤放回 GitHub 托管的执行机，box 只跑不带密钥的检查和浏览器测试；或者你确认接受这个信任范围。

### 建议的处理顺序

1. 问题 1：上下文误删。改动小，马上改善每天的聊天。
2. 问题 2：前台记忆核对引文。和问题 1 同一批测试。
3. 问题 3 里不需要你决定的部分，加上问题 12：默认 agent 改成 codex，接口不再新建 Claude 会话。
4. 问题 3 的方案 B 和每日任务进容器。需要你同意。
5. 问题 8：记忆备份。需要你定放在哪。
6. 问题 5：删除对话的清理清单。会删数据，先把清单给你确认。
7. 问题 4 和 7：锁内重活外移、系统提示保持不变。
8. 问题 10 和 11：部署密钥的去处、控制器源码不再公开。
9. 其余 P3 跟着相关改动顺手做；问题 6 等保留期一起设计。
