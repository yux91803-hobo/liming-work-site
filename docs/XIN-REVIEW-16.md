# 小芯改造：16 项走查与验收

范围以用户补充的 16 项为准。设计取舍和实现缺陷分别给出结论；保留取舍不等于遗漏实现。验证日期：北京时间 2026-11-07。正式发布结果由 PR #78 的生产流水线记录。

| 项 | 问题 | 本次处理与判断 | 验证 |
|---|---|---|---|
| 1 | 权限边界 | 后台模型和 MCP 进入独立 mount/PID 容器；只写副本与私有 home/tmp/io。控制目录、宿主进程和长期 key 不映射。长期 key 只在控制器，任务使用限接口、模型和次数的短期代理。前台、每日任务保持用户已确认的完全放权。 | 真实云电脑负向探针：不能读控制目录、写原项目或看到宿主进程；能写副本。 |
| 2 | 插话 | 改为 app-server，每个活跃轮次一个服务；原生 turn/steer，保留默认排队。消息 ID、续接和重试持久化。 | 真实模型在同一轮收到补充后把最终文件从 FIRST 改为 SECOND；浏览器队列刷新/补充测试。 |
| 3 | 插件 | 只显式开放 REA 静态分析白名单，插件与模型同容器降权运行；不开放设备或其它插件。 | 真 REA/Ghidra 打开 ELF、查 main，原二进制校验值不变。 |
| 4 | 同项目并发 | 单人 STM32 场景继续串行，目录规范化，嵌套目录也互斥。副本写回检查并发修改，冲突和删除需明确决定。暂不引入 worktree 合并复杂度。 | 并发上限、同目录排队、停止待退出、写回冲突和备份回归。 |
| 5 | 路由 | 保留前台 DeepSeek / max，按任务类型分配候选，检查避开实际作者模型，尊重点名。统计包含实际成功、耗时、回退及可获得的 token 增量。 | 路由/看图/回退/点名测试。每类别约 30–50 个有代表性的人工核验样本可开始比较，但不足以直接自动改路由；还需留出集和可复现优势。 |
| 6 | 专业审查 | 前台转述不是事实；把用户原话单独交给作者和审查者。要求官方手册依据、源码行号和四项结论；控制器另外 make -B，检查新生成 hex，绑定最终源码摘要。 | GLM 实现 + Kimi 检查实际固件；官方手册摘录、寄存器模型与构建结果；没有把静态验证说成上板验证。 |
| 7 | 恢复与续租 | 本地 watchdog 加持久 DO alarm，活跃时续租，空闲撤销，撤租约失败继续重试。冷却期延后检查。恢复先清旧子进程，保留副本，最多自动恢复一次。 | 真实杀管理进程后恢复，ONE 没有重复写；乱序版本、租约失败、冷却回归。真实暂停/重启另行验收，不能由进程测试代替。 |
| 8 | 整条链路 | 正式站 Actions 使用 Secrets 登录网页，真实模型派后台任务，前台继续回复，关闭页面后检查任务和下载文件。测试站聊天仍不配置生产密钥。 | 生产部署必须通过实际联调；失败自动回滚。不能用 HTTP 200 或假接口代替。 |
| 9 | 锁与竞态 | 会话记录按 sid，任务、调度和任务索引按 tasks 锁；锁不删除，子进程不继承。修复锁外索引回写旧快照、运行元数据整份覆盖 steer/stop、任务未退出时删除记录等窗口。结束、停止和下一轮补充按同一锁提交。 | 并发发送、状态更新、锁持有者死亡、迟到收尾、停止/提问占用、索引与补充更新的回归。锁方向为会话→tasks，tasks 不回取会话锁。 |
| 10 | 成本 | 不擅自把用户指定的 max 改成 high。普通后台任务默认 60 分钟、并发 2；每任务默认 128 次推理请求，跨重试/恢复累计，控制器可配 XIN_TASK_REQUEST_LIMIT（上限 512）。耗尽后保留副本。 | 请求代理和预算跨续接测试。请求数/时长是技术预算，不是假装知道价格的人民币上限；前台/每日任务完全放权，不能宣称具备网关计费硬限额。 |
| 11 | 前台要求出错 | 用户原话与前台子任务描述分开保存，检查者能识别转述遗漏；以官方资料优先，检查任务保留更多完整要求，不能沿用前台的“默认映射”等假设。 | 固件真实案例纠正 CCMR1/CH2、复用和时钟；用户原话传播回归。 |
| 12 | 分身再派分身 | 暂不开放。显式关闭 Codex 默认开启的原生 multi_agent 与 multi_agent_v2，所有派工只经 xin task 的统一调度；后台桥只支持记忆与提问，不具备派任务、停止其它任务或写控制器的能力。 | 桥拒绝 task new/tell/stop；真实容器内核对原生分身开关为 false；并发上限与目录互斥测试。后续若开放，需统一树级预算、深度和取消语义。 |
| 13 | 每日任务 | 已并入同一任务系统、锁、队列、目录互斥和失败状态；按计划日期记结果，不在跨午夜时记错日期；重复触发不创建并行日任务。 | 每日任务 Codex、排队、重复触发、状态和日期回归。权限继续保持用户已有选择。 |
| 14 | 点名误判 | 识别保守的明确指令，排除假设、否定、引用、例子和问句；不确定时沿用默认模型，点名只影响当前轮次。 | “如果用 Kimi 的话”“为什么用 Kimi”“有人说…”等反例及明确点名正例。自然语言仍可能有歧义，不把正则当语义理解器。 |
| 15 | 多设备漏推 | 不再用一条全局最近轮询时间压掉所有订阅。订阅绑定设备，观看记录区分设备和标签页；只有本设备在看相同对话才略过本设备，其它设备照常投递；旧订阅无设备 ID 时宁可多提醒。 | 桌面在看、手机不在看、同设备后台标签关闭的测试；真实推送服务回执与手机实际显示分开报告。 |
| 16 | 记录增长 | 建版本化索引，任务锁内更新；活跃任务保留完整索引，结束任务只存摘要，原始历史按需读取。普通聊天变化不触发重读全部历史。不自动删除用户历史。 | 大前台记录不被轮询读取、索引更新/冷启动迁移、结束任务原始信息保留的测试。未来若任务达到万级或摘要索引仍明显影响延迟，再迁 SQLite/分页，不现在强加自动清理。 |

仍需明确区分：代码/编译/寄存器模型不是物理板验证；推送服务接受不是手机已经弹出；免费云电脑的强制运行上限不能由应用取消。所有发布和复测都在用户现有授权内执行，不要求用户逐个审批 PR。

## high / max 的真实小样本

同一个 DeepSeek V4.1 Flash，各用 high / max 回答三类相同问题（闲聊、GPIO 讲解、TIM3/PB5 配置），顺序交替，6 次均成功。high 合计输出 1608 token、耗时 17.849 秒；max 合计输出 1589 token、耗时 17.537 秒。这次样本没有显示把前台一律降到 high 会带来稳定收益；缓存命中不同，不能把差异直接当费用结论，也不能证明两种强度在复杂任务上质量相同。保持用户指定的 max，先用后台请求预算和实际用量约束。原始指标见 [xin-effort-smoke.json](xin-effort-smoke.json)，没有虚构人民币单价。
