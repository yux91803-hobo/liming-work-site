# Liming 工具箱 · STM32 学习工作台

自己学嵌入式用的网站，电脑、平板、手机都会用。工具箱里有 STM32 学习台和世界地图；首页标题栏上有个像素小人（小芯），能拖、能喂、能扔进学习台陪着。

2026-11-26 站长决定：小芯聊天（工作台、终端、云电脑上的 AI）和天启都删了，只留下页面上的这个小人。平板上的 AI 现在直接用 li、li2 两台云电脑，见 [tablet-setup](https://github.com/yux91803-hobo/tablet-setup) 仓库。以前的设计和记录在 `docs/` 里留作历史。

## 世界地图有什么

- 矢量、高德、卫星、高德卫星四种底图，支持搜索、定位、缩放、指北和点选国家；矢量地图默认视角就显示主要省州名称与省界，省名优先于相邻城市排布，放大后补充更多细节。高德与其他底图切换时，相机和标记同时转换坐标，保持原来的位置。
- 搜索结果支持方向键、Enter 和 Esc；改字、清空或点地图会取消旧搜索，迟到的结果不会覆盖新的操作。在线搜索失败时仍可查本地国家数据，跨日界线的国家也能正确聚焦。
- 矢量瓦片或样式加载失败时临时使用高德，不覆盖保存的底图偏好；浅色、深色跟随工具箱，深色地名保持清晰对比，细节随缩放出现。图层面板支持键盘与下滑关闭，手机允许浏览器缩放。

## STM32 学习台有什么

- **首页**：STM32F103ZET6 芯片引脚图（双击 / 双指放大），按分组列出开发板上的模块；点引脚看复用功能和板上接到哪里。
- **开发板**：原理图逐页翻看，22 个模块图，点脚看连接和作用。
- **外设页**（RCC、GPIO、EXTI、USART、I2C、TIM、DMA、ADC、SPI、FSMC）：要点 / 引脚 / 寄存器 / 代码 / 图。
  - 寄存器：位图计算器，点位改值，生成读-改-写代码和 HAL 写法，常用配置一键填好；I²C 时钟助手检查 STM32F103 的频率范围，CCR 向上取整以免超速，并显示实际 SCL，修改 DUTY 后同步重算。
  - 代码：完整的 .h / .c / main.c（寄存器版、HAL 版）和「代码推导」，可以「自己写」逐行练。
  - 图：参考手册框图、课件教学图，点开大图查看。
- **编程思维**（GPIO、定时器）：明确任务 → 查资料 → 规划 → 编写 → 验证五步；验证里粘贴自己写的函数，模拟器跑一遍指出问题。
- **硬件原理**：每个外设一张自绘结构图，按块讲解；I2C 等章节有「推导链」自主推导题。
- **搜索**：Ctrl/Cmd+K 或右上角，搜引脚、寄存器、代码、图；改词后立即回车也按最新输入定位，Tab 能到取消，方向键选择的结果会告知读屏。搜索、寄存器和看图叠开时只有最上层可操作，最后一层关闭后恢复滚动。
- **操作状态**：从任意代码模式都能切到要点、引脚、寄存器和图，切回来保留代码模式、驱动与文件；切换文件立即同步到地址，查寄存器、看图后逐层返回原文件和阅读位置。手机目录、搜索也计入返回层级，返回先关闭当前临时层，再退页面。
- **主题**：浅色、深色切换时，当前外设、引脚高亮和寄存器标签即时更新颜色，保留正在编辑或计算的内容；异常寄存器、模块链接也不会阻止页面加载。
- **返回**：返回键、浏览器 / 手机的返回按走过的路一层层退回；去的页面已经走过（GPIO → USART → GPIO），就直接退回到那里，返回时不会在同几页之间来回打转；同一页里换分页不算一层；回学习台首页就清空。电脑（宽屏）上返回键旁边一直有「回工具箱」；直接打开学习台时，左上角的「STM32F103 学习台」也能点回工具箱。
- **小芯（页面上的小人）**：首页的像素小助手，按参考图重画为黑色倒角芯片、银白顶边与中央凹口、暖金属引脚、四条小腿；常态双手对称平伸，举手只在动作中出现；常态直接采用图中的专注眼：较宽、略带圆角的暖白发光竖矩形，没有腮红；只有微笑、开心和喜欢时出现淡淡的双斜杠腮红，`> <` 只用于微笑。玩的时候会笑、开心、惊讶、疑惑、难过、生气，表情结束后恢复常态，保留眨眼；生气用连贯内压斜眉和半眯眼，收起的小脑袋也使用同一套造型。可以拖、喂、玩。拖到 STM32 卡片上松手，它就跟进学习台；学习台里背包点「收起来」，它躲到屏幕右边只露个小脑袋，点小脑袋又跳回来（刷新也还收着，下次再把它扔进来就出来）。

推导进度、粘贴的代码等只存在当前浏览器里，不跨设备同步。寄存器页面是计算器，没有连接真实开发板。

## 本地运行

需要 Node.js 20 或更新版本。静态预览和单元测试不需要安装依赖。

```sh
npm run dev        # 本地预览
npm run check      # 语法、本地引用、STM32 图片引用 + 单元测试
npm run test:e2e   # 浏览器端到端测试（需要 Python playwright + Chromium，先 npm run dev）
```

`/stm32` 使用与正式站一致的工具箱外壳；也可以直接打开 `/tools/stm32/`。

## 部署

由 GitHub Actions（`.github/workflows/deploy.yml`）完成，令牌在仓库 Secrets 里（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`）：

- 开 PR 到 `main`：检查通过后部署测试站 `liming-hub-staging`（只有 `*.workers.dev` 地址），并检查首页和工具页。
- 合并到 `main`：部署正式站 `liming-worldmap`（liming-work.com）；检查失败自动回滚到发布前记录的版本。
- Actions 页面可以手动运行，默认只 dry-run。

STM32 编译环境用 `scripts/vm/setup-stm32.sh` 装（li 上已经装好；换了新的云电脑就传上去跑一次）：装 `gcc-arm-none-eabi`，从 ST、ARM 官方仓库下固定版本的 CMSIS 头文件和启动文件，在 `/data/workspace/stm32-template` 放一个能直接 `make` 的空工程（链接脚本按 ZET6：Flash 512K、RAM 64K；`syscalls.c` 让 printf / malloc 能链接）。可以重复跑，不会覆盖自己改过的 `main.c`。

互传和协作中心删除时留下的 Cloudflare 资源（迁移 `v2` 已在两个站执行过）：D1 数据库 `liming-hub` 还在账号里，确认不要可以 `npx wrangler d1 delete liming-hub`；旧密钥 `TRANSFER_PASSWORD`、`TRANSFER_KEY`、`TRANSFER_PW_VERSION` 可以用 `npx wrangler secret delete <名字>` 删掉。

GitHub Actions 的 check / e2e / deploy 全部在 GitHub 自带的执行机（`ubuntu-latest`，公开仓库用它不收费）上运行；以前的自托管执行机（box、站长笔记本）2026-11-15 已删掉——仓库公开后任何人都能开 PR，自托管执行机会跑别人的代码。只跑 main 和本仓库分支的 PR，fork 来的 PR 不跑、拿不到密钥。Actions 日志公开可见：部署列表进日志前隐去账号邮箱（`scripts/ci-redact.mjs`）；旧日志可以在 Actions 页手动运行「Clean old logs」删掉（只删日志，运行记录留着）。PR 和 main 都完整检查当前代码；PR 通过后部署测试站，合并后还会核对代码树与两份 PR 通过证据，再做正式站冒烟检查（小芯真模型联调 2026-11-26 已删，站长不用小芯了）。证据缺失或代码不同就停止部署。每套合成浏览器检查的独立日志和预览服务日志会在失败时照常上传，保留一天。
