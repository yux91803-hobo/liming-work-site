## 世界地图有什么

- 矢量、高德、卫星、高德卫星四种底图，支持搜索、定位、缩放、指北和点选国家；矢量地图默认视角就显示主要省州名称与省界，省名优先于相邻城市排布，放大后补充更多细节。高德与其他底图切换时，相机和标记同时转换坐标，保持原来的位置。
- 搜索结果支持方向键、Enter 和 Esc；改字、清空或点地图会取消旧搜索，迟到的结果不会覆盖新的操作。在线搜索失败时仍可查本地国家数据，跨日界线的国家也能正确聚焦。
- 矢量瓦片或样式加载失败时临时使用高德，不覆盖保存的底图偏好；浅色、深色跟随工具箱，深色地名保持清晰对比，细节随缩放出现。图层面板支持键盘与下滑关闭，手机允许浏览器缩放。

## STM32 学习台有什么

- **首页**：STM32F103ZET6 芯片引脚图（双击 / 双指放大），按分组列出开发板上的模块；点引脚看复用功能和板上接到哪里。
- **开发板**：原理图逐页翻看，22 个模块图，点脚看连接和作用。
- **外设页**（RCC、GPIO、EXTI、USART、I2C、TIM、DMA、ADC、SPI、FSMC）：要点 / 引脚 / 寄存器 / 代码 / 图。
  - 寄存器：位图计算器，点位改值，生成读-改-写代码和 HAL 写法，常用配置一键填好；I²C 时钟助手检查 STM32F103 的频率范围，CCR 向上取整以免超速，并显示实际 SCL，修改 DUTY 后同步重算。
  - 代码：完整的 .h / .c / main.c（寄存器版、HAL 版）和「代码推导」，可以「自己写」逐行练。
  - 图：参考手册框图、课件教学图，点开大图查看。
- **编程思维**（GPIO、定时器）：明确任务 → 查资料 → 规划 → 编写 → 验证五步；验证里粘贴自己写的函数，模拟器跑一遍指出问题。
- **硬件原理**：每个外设一张自绘结构图，按块讲解；I2C 等章节有「推导链」自主推导题。
- **搜索**：Ctrl/Cmd+K 或右上角，搜引脚、寄存器、代码、图；改词后立即回车也按最新输入定位，Tab 能到取消，方向键选择的结果会告知读屏。搜索、寄存器和看图叠开时只有最上层可操作，最后一层关闭后恢复滚动。
- **操作状态**：从任意代码模式都能切到要点、引脚、寄存器和图，切回来保留代码模式、驱动与文件；切换文件立即同步到地址，查寄存器、看图后逐层返回原文件和阅读位置。手机目录、搜索也计入返回层级，返回先关闭当前临时层，再退页面。
- **主题**：浅色、深色切换时，当前外设、引脚高亮和寄存器标签即时更新颜色，保留正在编辑或计算的内容；异常寄存器、模块链接也不会阻止页面加载。
- **返回**：返回键、浏览器 / 手机的返回按走过的路一层层退回；去的页面已经走过（GPIO → USART → GPIO），就直接退回到那里，返回时不会在同几页之间来回打转；同一页里换分页不算一层；回学习台首页就清空。电脑（宽屏）上返回键旁边一直有「回工具箱」；直接打开学习台时，左上角的「STM32F103 学习台」也能点回工具箱。
- **小芯**：首页的像素小助手，按参考图重画为黑色倒角芯片、银白顶边与中央凹口、暖金属引脚、四条小腿；常态双手对称平伸，举手只在动作中出现；常态直接采用图中的专注眼：较宽、略带圆角的暖白发光竖矩形，没有腮红；只有微笑、开心和喜欢时出现淡淡的双斜杠腮红，`> <` 只用于微笑。微笑、专注、开心、冷静、星星眼和爱心眼均可由聊天指令和自编动作触发，表情结束后恢复常态，保留眨眼；生气用连贯内压斜眉和半眯眼，聊天头像和收起的小脑袋也使用同一套造型。可以拖、喂、玩。拖到 STM32 卡片上松手，它就跟进学习台；学习台里背包点「收起来」，它躲到屏幕右边只露个小脑袋，点小脑袋又跳回来（刷新也还收着，下次再把它扔进来就出来）。

## 小芯后台运行方式

- 2026-11-14 接手核对：[现状与安全审查](docs/xin-kernel-handover-review-2026-11-14.md)、[第二阶段实施计划](docs/superpowers/plans/2026-11-14-xin-kernel-stage2.md)。第一阶段已上线，状态与调度仍在旧控制器。待送达按对话分道：同一个对话先来后到，一个对话在忙不堵别的对话，电脑叫不醒或在冷却时才全部等着；文件删除/冲突写回展示具体清单，批准只适用于该清单与文件内容，变化后重新核对。浏览器诊断不记填写内容和网址参数，维护审计不另存命令正文。第二步先引入[所有权锁和记录](docs/superpowers/plans/2026-11-14-xin-owner-lock.md)，建库和 schema 升级也经过写权检查；[常驻状态进程与兼容桥](docs/superpowers/plans/2026-11-14-xin-state-bridge.md)已加入隔离验证路径，具名修改转交所有者，未持写权的数据库句柄原生只读；默认部署仍走旧模式，正式状态切换尚未开启。电脑维护、每日任务、天启能力保留；宿主授权 C 路线和后续隔离的安排以[已确认设计](docs/superpowers/specs/2026-11-14-xin-kernel-stage2-design.md)为准，不声称已经强隔离。[写者清单](docs/superpowers/plans/2026-11-14-xin-writer-inventory.md)：控制器里每一处直接写文件的地方都登记在 `test/xin-writers.json` 并标了类别，新加一处没登记测试就红。

- 2026-11-13 起（内核第 1 步，[设计](docs/xin-kernel-design.md)）：

  - 回复用 SSE 推送；回答仍是整段到的。
  - 开关是 `XIN_TRANSPORT`、`XIN_INBOX`。

- 后台完成以持久事件唤回 DeepSeek；小芯检查后交付、继续修正或安静结束。用户消息优先，完成版本与聊天/通知绑定，刷新不重复播报。自动续接每项最多两次，后台仍走统一调度器。
- 前台上下文检查点、聊天展示和长期记事本分开；旧轮次有来源索引，可用 `xin recall` 检索原文。完整架构与边界见 [运行说明](docs/xin-front-dispatcher.md)。

- 「你让 Gemini 4 Hydrogen 去画个奶龙」会先接单，再用 Antigravity 的 Gemini 4 Hydrogen（写网页用 high）在后台生成可交互网页（额度真实耗尽或 Gemini 卡住时才换别的执行模型）；前台优先 Hydrogen、Gemini 额度真实耗尽后用 DeepSeek，可继续聊天。进度查询读取真实任务状态，不报猜测百分比。
- 网页通过结构化语义派工 `xin task new --web` 交付自包含 HTML 与 `xin-web.json`。控制器在容器里真正用 Chromium 检查 1280/390 宽度、页面错误和点击变化（同一页面按顺序连续点击，每次点击后最多等 1.5 秒看预期变化；不过时说明实际看到的状态），最多返工两次；通过后才出现「我画好了」与预览链接。
- 预览是控制目录里的不可变快照，需站长登录，脚本在不共享站点权限的 iframe 中运行。下载的 HTML 可离线打开；不依赖常驻端口，任务进程和私有临时目录清理后预览仍保留。当前只支持自包含 HTML，不托管需要后端或外部资源的多文件应用。

- 前台默认 Antigravity Gemini 4 Hydrogen（medium），Gemini 额度真实耗尽后经 Responses API 用 DeepSeek V4.1 Flash / max，只聊天、读真实进度和调用结构化派工函数，不启动 shell/MCP。后台按类型选择模型，独立检查在启动和 fallback 时都避开实际作者模型，候选耗尽会等待，点名同作者会明确拒绝。请求模型与实际模型分别记录。模型统计用于人工调整，少量测试不会自动改变默认路由。
- 后台通过 Codex app-server 管理轮次。「立即补充」送入当前轮次；默认排队消息逐条发送，刷新可恢复，重试携带稳定消息编号。
- 切换对话会作废旧页面回调，旧发送结果保留在原会话；未提交成功的旧消息可从侧栏「未发送的消息」恢复。后台提问收到快速答复后同步消费旧问题，后续新问题照常保留。
- 后台任务在独立文件系统、PID 和网络容器中运行，只能写项目副本及私有 home/tmp/io。容器看不到小芯电脑上的本机服务（桌面、模型网关等）：推理经控制器的套接字代理，上网经出网代理且只能访问公网的 80/443，编译、网页验收和插件不联网。控制目录和宿主进程不映射；长期网关密钥只在控制器，容器使用限模型、限接口、限次数的临时推理凭证。首次配置云电脑运行 `scripts/vm/setup-xin-runtime.sh`；已在 Codex 0.166.0 / bubblewrap 0.12.0 上验证。
- **电脑维护**（`--kind system`，2026-11-12 起）：电脑本身的事（卡、磁盘满、程序或服务坏了、往系统里装软件、本机网关面板和签到积分、桌面上的程序）前台派这一类。它不进容器，直接在小芯电脑上做、能 sudo，直接查直接修、不先问；只有删站长的文件、花钱、对外发消息、删机器或快照、重启整台电脑要先问。别停 `instabox-guest-agent` 和 `workbuddy-gateway` 两个服务，控制器目录只看不改。几个电脑维护任务按目录 `WORK/system` 排队，同一时间只做一个；不带网页成品、网站登录和插件。
- 普通改动备份后写回；删除原文件或覆盖任务期间的改动，要点「允许这一次 / 拒绝」。写回写到一半出错会按清单从备份还原原项目；写回到一半被杀，下次收尾把已写回的算完成、补齐剩下的，不误报冲突。中断、停止和失败会保留副本供续接。同一项目及嵌套目录仍串行执行；没有引入并行 worktree。
- 任务副本放在控制器旁边的 `~/.xin-tasks/`（不在系统临时目录，免得被 InstaBox 的 10 天清理删掉一部分）。做完的任务副本 7 天后在每日清理时删（结果已写回项目，写回前的备份留 30 天）；没做成、停了、等确认的留到删对话为止。做完时记下用量，删了副本也照样显示。
- 干活中途遇到临时错误（断线、网关 5xx、限流），控制器分别等 1、4、15 分钟用同一个副本和会话接着做，卡片写「连接出错，稍后接着做」；预算用完、超时等照旧算没做成。时限从第一次开工算，不因重试延长。
- 后台中途问你问题，等 10 分钟没回就记成「待处理」、结束这一轮，云电脑可以睡；你回答后接着同一个会话做。
- 「待处理」只剩三种：要批准的操作（删你的数据、推 main、部署、花钱、对外发消息、写回时删文件或覆盖冲突）、登录、提问；最多等 30 分钟，过了任务自己停下（结果里写明当时问的什么），不再提醒，之后回一句照样接着做。能自己定的不问，做不了直接结束说原因；中途断了两次、复核找不到模型直接算没做成。工作台和首页显示「剩 N 分钟」。
- 需要静态逆向分析时，派任务加 `--plugin rea`，只开放明确列出的分析接口。MCP 与模型工具都在同一容器里，不能改控制器或设备。
- 请求预算默认每任务 128 次及 150 万已报告输入加输出 token，跨续接/恢复和完成推理累计；后台默认 60 分钟、并发 2，不擅自降低 max。实际 token 记录用于后续比较，不把请求数当成人民币费用限额。
- 任务索引在 tasks 锁内更新，结束任务压成摘要，完整历史按需读取，不自动删除。用户原话单独传给作者和检查者，避免前台转述成为唯一依据。
- 本地 watchdog 与 Cloudflare 持久 alarm 在网页关闭后继续监督任务、重试通知和更新活动租约。进程恢复先清理遗留子进程、检查已完成步骤；停止后等实际退出才释放目录。每日任务进入同一个调度器，用自己的目录 `/data/workspace/daily`，跑的时候不挡别的后台任务。
- 控制器每次调用先看状态库有没有要补写的，没有就不拿写锁，别的进程在做重活时轮询不再排队；网页取进度带上次读到的字节位置，只读新增的部分。
- STM32 实现任务由控制器对最终源码强制重编译并检查本次生成的有效 HEX / ARM ELF / BIN；支持根目录或嵌套 Make/CMake 工程，多个入口用根目录 `xin-build.json` 指定 `system`、`directory` 和可选 `artifacts`，无法识别时明确失败。检查任务另写 `xin-review.json`，逐项记录时钟、引脚/复用、外设时钟和中断的手册依据、源码位置与结论。编译和静态检查不能代替上板验证。
- 推送按设备和标签页识别是否正在看同一对话；电脑在看不会压掉手机，旧订阅没有设备标识时照常投递。通知出站记录有版本和回执，过期响应不删除新订阅。
- 后台桥固定 io 目录句柄，请求按 fd 校验读取，回复用独占临时文件写完再原子发布，不跟随软链接或覆盖已有条目。进程清理检查整个任务 session，组长先退出或孙进程更换进程组也须清理完才释放目录，使用 pidfd 防止 PID 复用。
- Codex 原生分身显式关闭，派工只通过小芯统一任务调度；后台分身不能再次派工。
- 全部 16 项的结论与证据见 [走查表](docs/XIN-REVIEW-16.md)。
- InstaBox 免费机的强制运行上限仍由平台控制，冷却期间 alarm 会等待再唤醒。Web Push 的投递回执不等于手机已经显示通知。

## 部署

由 GitHub Actions（`.github/workflows/deploy.yml`）完成，令牌在仓库 Secrets 里：

- 开 PR 到 `main`：检查通过后部署测试站 `liming-hub-staging`（只有 `*.workers.dev` 地址），并检查首页和 `/tools/stm32/`。
- 合并到 `main`：部署正式站 `liming-worldmap`（liming-work.com）；检查失败自动回滚到发布前记录的版本。
- Actions 页面可以手动运行，默认只 dry-run。

### 小芯聊天要配的东西

| 放在哪 | 名字 | 是什么 |
|---|---|---|
| GitHub 仓库 Secrets | `XIN_OWNER_PASSWORD` | 网站登录密码，至少 12 位 |
| GitHub 仓库 Secrets | `XIN_INSTABOX_API_KEY` | InstaBox 的 API key（`ibk_…`） |
| 云电脑里 | AI 的 key | Codex / Claude Code 自己的登录或 key；推荐用 InstaBox 后台的 Secrets（代理模式），云电脑里只看到占位符 |

两个 GitHub Secrets 都配了，合并到 `main` 时 Actions 才把它们写进正式站（测试站不写，功能关着）。正式站还有两个定时任务（`wrangler.jsonc` 的 `triggers.crons`，UTC）：`55 0 * * *` 叫醒云电脑，`10 1,13 * * *` 让小芯做每日任务；测试站没有。云电脑默认找名字叫 `li` 的那台（`wrangler.jsonc` 里的 `XIN_MACHINE`）。
云电脑里的管理脚本 `vm-agent.mjs` 和它 import 的各个模块不用手动装：网站第一次用、或者脚本改过时，会按内容摘要命名后自动传到 `/data/home/.xin/agent/`（Worker 按 import 递归找出全部本地模块，缺文件或循环引用会明确报错）。对话记录存在云电脑的 `/data/home/.xin/`，AI 的工作目录是 `/data/workspace`（网站上「小芯的文件」只能看、只能下载这里面的）。
同一对话的发送、改名、归档、删除和后台状态更新用 Linux 的 `flock` 串行处理（InstaBox 的 Debian 镜像自带）；两个设备同时发送时，后一个会明确提示上一句未完成，避免漏记历史。自动清理只处理 `~/.xin/agent-sessions/` 登记过、已没有网页对话关联且超过一小时未更新的 AI 记录：现有网页对话会自动补登记，其他命令行任务和无法确认归属的旧记录保留。75 秒自动重连只用于尚未开始工作的 CLI：收到任务开始或模型进展后，不再由网页重放这一轮，长思考期间暂时没有输出也不会被网页打断；后续网络超时和重试交给 CLI 自己处理，手动停止照常可用。
STM32 编译环境用 `scripts/vm/setup-stm32.sh` 装（已经装好；换了新的云电脑就把它传到 `/data/home/.xin/setup-stm32.sh` 跑一次）：装 `gcc-arm-none-eabi`，从 ST、ARM 官方仓库下固定版本的 CMSIS 头文件和启动文件，在 `/data/workspace/stm32-template` 放一个能直接 `make` 的空工程（链接脚本按 ZET6：Flash 512K、RAM 64K；`syscalls.c` 让 printf / malloc 能链接）。可以重复跑，不会覆盖自己改过的 `main.c`。
AI 在云电脑里是完全放权的（不经确认就执行命令），云电脑里别放重要的东西，也别放 InstaBox key。
做完提醒用的是标准 Web Push：VAPID 钥匙在云电脑的 `/data/home/.xin/push/vapid.json` 里生成（私钥不离开云电脑，文件只有自己能读），浏览器的订阅存在同目录的 `subs.json`，推送从云电脑直接发给浏览器厂商的推送服务；网站只多了一个 `/sw.js`（只管弹通知，不拦截任何请求）。

互传和协作中心删除时留下的 Cloudflare 资源（迁移 `v2` 已在两个站执行过）：D1 数据库 `liming-hub` 还在账号里，确认不要可以 `npx wrangler d1 delete liming-hub`；旧密钥 `TRANSFER_PASSWORD`、`TRANSFER_KEY`、`TRANSFER_PW_VERSION` 可以用 `npx wrangler secret delete <名字>` 删掉。

GitHub Actions 的 check / e2e / deploy 全部在 `[self-hosted, box]` 的 `box-liming-work-site` 上运行。PR 和 main 都完整检查当前代码；PR 通过后部署测试站，合并后还会核对代码树与两份 PR 通过证据，再做正式站冒烟和真实模型联调。证据缺失或代码不同就停止部署。每套合成浏览器检查的独立日志和预览服务日志会在失败时照常上传，保留一天；正式站的真实聊天不放进这份报告。
